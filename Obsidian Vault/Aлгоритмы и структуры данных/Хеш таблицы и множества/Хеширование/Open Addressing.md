## Алгоритм вставки в хеш-таблицу(алгоритм линейного пробирования)

Сначала вычисляем хеш-индекс. Далее мы будем итерироваться по всем слотам линейно, по одному, начиная с хеш-индекса — ведь именно там с наибольшей вероятностью можно найти нужный слот.

Итак, начинаем итерироваться линейно. Одно из базовых условий остановки — когда индекс итерации снова станет равен хеш-индексу. То есть мы прошли один «круг», обошли все слоты, но так и не нашли подходящего. В этом случае операция вставки завершается неудачей(Таблица переполнена и нужен rehashing).

На каждой итерации мы обрабатываем возможные состояния слота, их всего 3: **свободен**, **оккупирован** или **удалён**.

- Если слот **свободен**, то всё просто — мы занимаем его, выставляем для него новое состояние как оккупирован и останавливаем итерацию.
- Если слот **оккупирован**, сравниваем ключ в слоте с ключом, который хотим вставить:
  - Если ключи совпадают — вставка не требуется, ключ уже присутствует.
  - Если ключи разные — продолжаем итерацию(линейное пробирование).
- Если слот находится в состоянии **Deleted**, то, как и в случае со свободным слотом, мы можем вставить ключ в этот слот и завершить итерацию.

## Алгоритм поиска в таблице(линейное пробирование)

Cначала мы вычисляем хеш-индекс. Нам нужно линейно проитерироваться по всем слотам и проверять их состояния (всего три: **свободен**, **занят**, **удалён**).

Мы начинаем итерирование с хеш-индекса, потому что с наибольшей вероятностью искомый элемент находится именно там.

Одно из базовых условий остановки итерации — достижение индексом исходного хеш-индекса. Это означает, что мы прошли полный "круг", обошли все слоты, но так и не нашли нужный элемент. В этом случае поиск завершается: элемент **не найден**.

На каждой итерации мы обрабатываем текущее состояние слота:

- Если слот **занят**, сравниваем ключ в слоте с искомым ключом:
  - Если ключи совпадают — элемент найден, **поиск успешен**.
  - Если ключи различаются — переходим к следующему слоту.
  
- Если слот **свободен** — это означает, что искомого элемента в таблице нет. Поиск завершается: **элемент не найден**.  
  *(Пояснение: если бы элемент был вставлен ранее, он не мог бы "перепрыгнуть" через пустой слот при линейном пробировании.)*

- Если слот помечен как **удалён** — продолжаем итерацию.  
  *(Пояснение: удалённый слот не означает конец цепочки — за ним может находиться нужный элемент.)*

**Ключевые принципы:**
- Каждая ячейка содержит либо элемент, либо помечена как пустая
- При коллизии ищется следующая свободная ячейка по определенному алгоритму
- Коэффициент заполнения обычно не превышает 0.7-0.8

## Методы probing (зондирования)

### 1. Линейное пробирование (Linear Probing)
**Характеристики:**
- Простая реализация
- Проблема **первичной кластеризации** - образуются длинные последовательности занятых ячеек
- Время поиска увеличивается при высоком коэффициенте заполнения

### 2. Квадратичное пробирование (Quadratic Probing)
**Характеристики:**
- Уменьшает первичную кластеризацию
- Может не найти свободную ячейку даже если она есть (проблема вторичной кластеризации)
- Константы c1 и c2 обычно выбирают c1 = c2 = 0.5

### 3. Двойное хеширование (Double Hashing)
**Характеристики:**
- Наиболее эффективный метод
- Требует две хеш-функции
- Минимизирует кластеризацию

### Перехеширование (Rehashing)
```python
def rehash(self):
    """Полное перехеширование таблицы"""
    old_table = self.table
    self.table = [None] * self.size
    self.count = 0
    
    for item in old_table:
        if item is not None and item is not self.deleted:
            self.insert(item[0], item[1])
```

### Выбор размера таблицы
Рекомендуется использовать простые числа для размера таблицы, чтобы уменьшить кластеризацию.

## 📊 Анализ сложности

| Операция | Средний случай | Худший случай |
|----------|----------------|---------------|
| Вставка  | O(1)           | O(n)          |
| Поиск    | O(1)           | O(n)          |
| Удаление | O(1)           | O(n)          |

**Зависимость от коэффициента заполнения (α):**
- При α < 0.7: операции близки к O(1)
- При α > 0.8: производительность значительно падает

## 🎯 Сравнение с методом цепочек

**Преимущества open addressing:**
- Не требует дополнительной памяти для указателей
- Лучшая локальность ссылок (кэш-дружественность)
- Проще в реализации для небольших таблиц

**Недостатки:**
- Чувствительность к коэффициенту заполнения
- Сложнее удаление элементов
- Может потребовать перехеширования
