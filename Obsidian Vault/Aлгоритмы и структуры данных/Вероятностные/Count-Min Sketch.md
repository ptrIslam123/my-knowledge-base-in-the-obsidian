# **Count-Min Sketch (CMS)**  
## *Вероятностная структура данных для оценки частот элементов в потоке*

> 🔹 **Цель**: оценить частоту (количество вхождений) любого элемента `x` в потоке:  
> $$
\hat{f}(x) \approx f(x) = \#\{ i : x_i = x \}
$$ 
> при этом используя **мало памяти**, работая **онлайн**, и допуская **ограниченную ошибку «в большую сторону»**.

> 🔹 **Ключевая особенность**:  
> \[
\hat{f}(x) \ge f(x) \quad \text{(никогда не занижает!)}  
\]  
> но может завышать из-за **коллизий хешей**.

---

## 🔧 1. Параметры и настройка точности

Алгоритм настраивается двумя параметрами:

| Параметр | Обозначение | Роль | Типичные значения |
|---------|-------------|------|-------------------|
| **Число хеш-функций** | `d` | Число строк («слоёв») в таблице | `d = ⌈ln(1/δ)⌉` |
| **Ширина таблицы** | `w` | Число ячеек в каждой строке | `w = ⌈e / ε⌉` |

где:
- `ε` — **максимально допустимая относительная ошибка** (`f̂(x) ≤ f(x) + ε·‖f‖₁` с высокой вероятностью),
- `δ` — **вероятность превышения ошибки** (`Pr[ошибка > ε·‖f‖₁] ≤ δ`),
- `‖f‖₁ = Σₓ f(x)` — **L1-норма**, т.е. **общее число элементов в потоке** (не уникальных!).

> ✅ Пример:  
> Хочу ошибку ≤ 1% от общего числа событий (`ε = 0.01`) с вероятностью ≥ 99% (`δ = 0.01`).  
> Тогда:  
> - `d = ⌈ln(1/0.01)⌉ = ⌈4.605⌉ = 5`  
> - `w = ⌈e / 0.01⌉ ≈ ⌈271.8⌉ = 272`  
> → Память: `d × w = 5 × 272 = 1360` целых чисел (при 4 байта/ячейка → **~5.3 КБ**).

---

## 📐 2. Структура данных

CMS — это **двумерная таблица (матрица)** счётчиков:

```
          0    1    2    …    w−1
       +----+----+----+-----+-----+
  h₁ → | c₁₀| c₁₁| c₁₂| ... |c₁,w−1|
  h₂ → | c₂₀| c₂₁| c₂₂| ... |c₂,w−1|
   ⋮   |  ⋮ |  ⋮ |  ⋮ |     |   ⋮ |
  h_d →| c_d0|c_d1|c_d2| ... |c_d,w−1|
       +----+----+----+-----+-----+
```

- Размер: `d` строк × `w` столбцов.
- Все `c_{i,j}` — целые числа ≥ 0 (обычно `uint32` или `uint64`).
- Каждая строка `i` имеет **свою независимую хеш-функцию** `h_i(x)`, отображающую элементы в `[0, w−1]`.

> 💡 Требования к хеш-функциям:
> - **Независимы** между собой (желательно из универсального семейства, например, `h_i(x) = ((a_i·x + b_i) mod p) mod w`).
> - **Равномерное распределение**.
> - Быстрые (MurmurHash3, xxHash — часто берут разные seed’ы как `h₁, h₂, …`).

---

## 🔄 3. Операции

### ✅ 3.1. **Добавление элемента** `x`

Для каждой строки `i = 1..d`:
1. Вычислить хеш: `j = h_i(x)`
2. Инкрементировать счётчик: `c_{i,j} += 1`

```python
def add(x):
    for i in range(d):
        j = h[i](x)       # h[i] — i-я хеш-функция
        C[i][j] += 1
```

- Время: **O(d)** = O(log(1/δ)) — константа на практике (обычно `d = 4..10`).
- Память не растёт — только инкременты.

---

### ✅ 3.2. **Оценка частоты** `f̂(x)`

Для элемента `x`:
1. Для каждой строки `i`: вычислить `j_i = h_i(x)`
2. Прочитать `c_{i, j_i}`
3. Вернуть **минимум** по всем строкам:

\[
\hat{f}(x) = \min_{1 \le i \le d} \; c_{i,\, h_i(x)}
\]

```python
def estimate(x):
    return min(C[i][h[i](x)] for i in range(d))
```

> ❗ Почему **минимум**?  
> → Потому что каждая ячейка `c_{i,j}` накапливает **частоту всех элементов, хеширующихся в `j` по `h_i`**.  
> → Из-за коллизий `c_{i, h_i(x)} ≥ f(x)` для всех `i`.  
> → Но **хотя бы в одной строке** коллизий может быть мало — и минимум даёт наименее завышенную оценку.

## 📊 4. Почему это работает? Теоретические гарантии

### 🔹 Обозначения
- `X` — множество возможных элементов (потенциально бесконечное).
- `f(x)` — истинная частота элемента `x`.
- `N = ‖f‖₁ = Σ_{x∈X} f(x)` — длина потока.
- `c_{i, h_i(x)}` — значение в строке `i` для `x`.

### 🔹 Основное наблюдение
Для фиксированной строки `i`:  
\[
c_{i, h_i(x)} = f(x) + \sum_{y \ne x \atop h_i(y) = h_i(x)} f(y)
\]
Т.е. **настоящая частота + шум от коллизий**.

Поскольку `h_i` равномерна, для любого `y ≠ x`:  
\[
\Pr\big(h_i(y) = h_i(x)\big) = \frac{1}{w}
\]

→ Ожидаемое значение шума в строке `i`:
\[
\mathbb{E}[\text{шум}_i] = \sum_{y \ne x} f(y) \cdot \frac{1}{w} = \frac{N - f(x)}{w} \le \frac{N}{w}
\]

→ По неравенству Маркова:
\[
\Pr\left(c_{i, h_i(x)} > f(x) + \frac{N}{\varepsilon w} \right) \le \varepsilon
\]
(точнее, через неравенство Чебышёва или Хёфдинга — но стандартный вывод использует:

\[
\Pr\left(c_{i, h_i(x)} > f(x) + \varepsilon N \right) \le \frac{1}{e}
\quad \text{при } w = \lceil e / \varepsilon \rceil
\]

Тогда, поскольку строки **независимы**:

\[
\Pr\left( \forall i: c_{i, h_i(x)} > f(x) + \varepsilon N \right) \le \left(\frac{1}{e}\right)^d \le \delta
\quad \text{при } d = \lceil \ln(1/\delta) \rceil
\]

→ С вероятностью ≥ `1 − δ`:
\[
\exists\, i: c_{i, h_i(x)} \le f(x) + \varepsilon N
\;\Rightarrow\;
\hat{f}(x) = \min_i c_{i, h_i(x)} \le f(x) + \varepsilon N
\]

И так как `c_{i, h_i(x)} ≥ f(x)` всегда (счётчики только растут), получаем:

\[
\boxed{
f(x) \le \hat{f}(x) \le f(x) + \varepsilon \cdot \|f\|_1 \quad \text{с вероятностью } \ge 1 - \delta
}
\]

> 📌 Это **гарантия точности в L1-норме** — ошибка не более `ε·N`, где `N` — **общее число событий**, а не число уникальных!

## 🎯 5. Пример работы (вручную)

Пусть: `d = 2`, `w = 4`, хеши (условно):
- `h₁(x) = hash(x) mod 4`  
- `h₂(x) = (hash(x) // 4) mod 4`

Таблица `C` (2×4), изначально нули.

Поток: `["A", "B", "A", "C", "B", "A"]`

| Шаг | Элемент | h₁ | h₂ | Обновление C[1][h₁] | Обновление C[2][h₂] | C после |
|-----|---------|----|----|----------------------|----------------------|---------|
| 1   | A       | 2  | 0  | C[1][2] = 1          | C[2][0] = 1          | [[0,0,1,0], [1,0,0,0]] |
| 2   | B       | 0  | 3  | C[1][0] = 1          | C[2][3] = 1          | [[1,0,1,0], [1,0,0,1]] |
| 3   | A       | 2  | 0  | C[1][2] = 2          | C[2][0] = 2          | [[1,0,2,0], [2,0,0,1]] |
| 4   | C       | 1  | 2  | C[1][1] = 1          | C[2][2] = 1          | [[1,1,2,0], [2,0,1,1]] |
| 5   | B       | 0  | 3  | C[1][0] = 2          | C[2][3] = 2          | [[2,1,2,0], [2,0,1,2]] |
| 6   | A       | 2  | 0  | C[1][2] = 3          | C[2][0] = 3          | [[2,1,3,0], [3,0,1,2]] |

Теперь оценим:
- `f̂(A) = min(C[1][2], C[2][0]) = min(3, 3) = 3` ✅ (точно)
- `f̂(B) = min(C[1][0], C[2][3]) = min(2, 2) = 2` ✅
- `f̂(C) = min(C[1][1], C[2][2]) = min(1, 1) = 1` ✅

А если добавить `D` с `h₁(D)=2`, `h₂(D)=0` (коллизия с A):
- После `add(D)`: C[1][2]=4, C[2][0]=4
- `f̂(A) = min(4,4) = 4` ❌ (завышено: истинное `f(A)=3`)
- `f̂(D) = 4` (если `D` единственный — тоже завышено)

→ **Завышение из-за коллизий** — неизбежная плата за компактность.

## 🛠️ 6. Расширенные операции

### ✅ 6.1. **Объединение (merge) двух CMS**
Если `CMS₁` и `CMS₂` имеют **одинаковые `d`, `w` и хеш-функции**, то:
\[
\text{CMS}_{1+2}[i][j] = \text{CMS}_1[i][j] + \text{CMS}_2[i][j]
\]
→ Можно агрегировать по шардам, машинам, времени.

### ✅ 6.2. **Оценка топ-K частых элементов**
CMS **не хранит элементы**, поэтому:
- Нужен вспомогательный список кандидатов (например, через **SpaceSaving** или **Lossy Counting**),
- Или сканировать все возможные `x` (если домен мал),
- Или использовать **CMS + heap**: при добавлении `x` обновлять `f̂(x)` и поддерживать топ-K.

> ⚠️ Просто взять `K` ячеек с максимальными значениями — **нельзя**: это не соответствует `K` элементам!

### ✅ 6.3. **Поддержка удалений (Turnstile Model)**
Если поток может содержать **отрицательные обновления** (`add(x, +1)`, `add(x, −1)`), то:
- Храним счётчики как **целые со знаком** (`int32`/`int64`),
- Операция `add(x, Δ)` делает `c_{i, h_i(x)} += Δ`,
- Гарантии сохраняются, если **итоговые частоты ≥ 0**.

→ Это **Count-Min Sketch в режиме «turnstile»**.

## 📈 7. Сравнение с другими алгоритмами

| Метод | Оценивает | Память | Ошибка | Направление ошибки | Поддержка удалений | Merge |
|-------|-----------|--------|--------|---------------------|--------------------|-------|
| **Count-Min Sketch** | `f(x)` (частота) | `O((1/ε)·log(1/δ))` | `≤ ε·N` | **только вверх** | ✅ (turnstile) | ✅ |
| **Count-Sketch** | `f(x)` | `O((1/ε²)·log(1/δ))` | `≤ ε·‖f‖₂` | вверх/вниз | ✅ | ✅ |
| **HyperLogLog** | `|{x}|` (уникальные) | `O(log log N)` | `~1.04/√m` | ± | ❌ | ✅ |
| **Bloom Filter** | `x ∈ S?` | `O(N·log(1/δ))` | ложные срабатывания | — | ❌ | ✅ (OR) |
| Точный `HashMap` | `f(x)` | `O(U)` (U = уникальных) | 0 | — | ✅ | ❌ (дорого) |

> Где:
> - `N = ‖f‖₁` — длина потока,
> - `‖f‖₂ = √(Σ f(x)²)` — L2-норма (чувствительна к выбросам),
> - Count-Sketch лучше при **высокой дисперсии** (например, power-law), так как ошибка в L2.

## ⚠️ 8. Ограничения и подводные камни

| Проблема | Последствия | Как смягчить |
|---------|-------------|--------------|
| **Завышение частот** | `f̂(x) >> f(x)` для редких `x`, если много коллизий | Увеличить `w`, использовать `Conservative Update` |
| **Не подходит для редких элементов** | Ошибка `ε·N` может быть >> `f(x)` при малом `f(x)` | Комбинировать с **Lossy Counting** или **Sample+CMS** |
| **Требует хорошего хеша** | Плохой хеш → систематические коллизии → смещение | Использовать криптостойкие/универсальные хеши |
| **Не хранит элементы** | Нельзя перечислить топ-K без доп. структур | Добавить вспомогательный heap или filter |

### 🔹 Conservative Update (CU-CMS) — улучшение для частых элементов
При добавлении `x`:
```python
current = estimate(x)     # min_i C[i][h_i(x)]
for i in range(d):
    if C[i][h_i(x)] == current:
        C[i][h_i(x)] += 1
```
→ Обновляем **только те строки, где значение = текущей оценке**.  
→ Сильно снижает завышение для частых элементов, но **ломает линейность** (merge становится неточным).

## 💻 10. Простая реализация на Python

```python
import mmh3  # MurmurHash3

class CountMinSketch:
    def __init__(self, epsilon=0.01, delta=0.01, seed=0):
        self.epsilon = epsilon
        self.delta = delta
        self.w = int(2.71828 / epsilon) + 1   # w = ⌈e/ε⌉
        self.d = int(__import__('math').ceil(__import__('math').log(1/delta)))  # d = ⌈ln(1/δ)⌉
        self.C = [[0] * self.w for _ in range(self.d)]
        self.seed = seed

    def _hash(self, x, i):
        # i-я хеш-функция: меняем seed
        return mmh3.hash(str(x), seed=self.seed + i) % self.w

    def add(self, x, count=1):
        for i in range(self.d):
            j = self._hash(x, i)
            self.C[i][j] += count

    def estimate(self, x):
        return min(self.C[i][self._hash(x, i)] for i in range(self.d))

    def __add__(self, other):
        # Объединение (требует одинаковых w, d, seed!)
        assert self.w == other.w and self.d == other.d
        cms = CountMinSketch(self.epsilon, self.delta, self.seed)
        for i in range(self.d):
            for j in range(self.w):
                cms.C[i][j] = self.C[i][j] + other.C[i][j]
        return cms
```

> ✅ Проверка:
> ```python
> cms = CountMinSketch(epsilon=0.1, delta=0.01)
> for x in ["A"]*1000 + ["B"]*500 + ["C"]*10:
>     cms.add(x)
> print(cms.estimate("A"))  # ≈1000
> print(cms.estimate("C"))  # ≥10 (может быть 15–30 при коллизиях)
> ```

## ✅ Кратко для конспекта (шпаргалка)

> **Count-Min Sketch** — таблица `d × w` счётчиков.  
> - `add(x)`: для каждого `i=1..d` → `C[i][h_i(x)]++`  
> - `estimate(x)`: `min_i C[i][h_i(x)]`  
> - Гарантия: `f(x) ≤ f̂(x) ≤ f(x) + ε·N` с вероятностью ≥ `1−δ`  
> - Память: `O((1/ε)·log(1/δ))`  
> - Merge: поэлементное сложение  
> - Используется для частот, топ-K, аномалий.
