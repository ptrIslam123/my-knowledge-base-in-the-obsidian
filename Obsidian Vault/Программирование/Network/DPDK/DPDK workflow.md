
# Полный Workflow пакета и прединициализации в DPDK

## Прединициализация (до старта NIC)

### Шаг 1: Создание `mempool`

Приложение создаёт `rte_mempool` — пул памяти для буферов.

```c
struct rte_mempool *mbuf_pool = rte_pktmbuf_pool_create(
    "MBUF_POOL",        // Имя
    NUM_MBUFS,          // Количество mbuf (например, 8192)
    MBUF_CACHE_SIZE,    // Размер кэша (например, 256)
    0,                  // Приватный размер
    RTE_MBUF_DEFAULT_BUF_SIZE,  // Размер буфера (2048)
    rte_socket_id()     // NUMA-узел
);
```

**Что происходит:**
- Выделяется **один большой кусок памяти** в hugepages
- Этот кусок разбивается на **N буферов** фиксированного размера
- Каждый буфер содержит:
  - **`rte_mbuf`** (метаданные: длина, оффлоады, указатели)
  - **Данные** (payload пакета) — сразу после `rte_mbuf`

**Визуально:**
```
mempool (hugepages):
┌─────────────────────────────────────────────────────────┐
│ [rte_mbuf_0][data_0] │ [rte_mbuf_1][data_1] │ ...       │
└─────────────────────────────────────────────────────────┘
```

---

### Шаг 2: Настройка RX-очередей

Приложение настраивает каждую RX-очередь:

```c
rte_eth_rx_queue_setup(
    port_id,            // Порт
    queue_id,           // Номер очереди
    nb_rx_desc,         // Количество дескрипторов (512)
    socket_id,          // NUMA-узел
    &rx_conf,           // Конфигурация очереди
    mbuf_pool           // Пул mbuf
);
```

**Что происходит внутри:**

1. **Создаётся RX-кольцо** — массив дескрипторов (например, 512 штук) в памяти.
2. **Каждый дескриптор привязывается к `rte_mbuf` из пула:**
   ```
   Дескриптор 0 → mbuf_0 (buf_addr = &data_0)
   Дескриптор 1 → mbuf_1 (buf_addr = &data_1)
   Дескриптор 2 → mbuf_2 (buf_addr = &data_2)
   ...
   Дескриптор 511 → mbuf_511
   ```
3. **Драйвер записывает в дескрипторы физические адреса буферов** (`buf_addr`).

**Визуально:**
```
mempool:                    RX-кольцо (очередь 0):
┌──────────────┐           ┌─────────────────────────┐
│ rte_mbuf_0   │◄──────────│ Дескриптор 0            │
│ rte_mbuf_1   │◄──────────│ Дескриптор 1            │
│ rte_mbuf_2   │◄──────────│ Дескриптор 2            │
│ ...          │           │ ...                     │
│ rte_mbuf_511 │◄──────────│ Дескриптор 511          │
└──────────────┘           └─────────────────────────┘
```

---

### Шаг 3: Настройка RSS и RETA

```c
struct rte_eth_rss_conf rss_conf = {
    .rss_key = rss_key,        // 40 байт ключа
    .rss_key_len = 40,
    .rss_hf = RTE_ETH_RSS_IP | RTE_ETH_RSS_TCP,  // Что хэшировать
};

rte_eth_dev_rss_hash_update(port_id, &rss_conf);
```

**RETA** (Redirection Table) заполняется автоматически или вручную:
```
RETA[0] = 0    (хэш % 128 == 0 → очередь 0)
RETA[1] = 1    (хэш % 128 == 1 → очередь 1)
RETA[2] = 2    (хэш % 128 == 2 → очередь 2)
RETA[3] = 3    (хэш % 128 == 3 → очередь 3)
RETA[4] = 0    (хэш % 128 == 4 → очередь 0)
...
```

---

### Шаг 4: Запуск NIC

```c
rte_eth_dev_start(port_id);
```

**Теперь NIC готова принимать пакеты.**

## Приход пакета (RX)

### Шаг 5: Пакет приходит на физический порт

```
[Сеть] → [Физический порт NIC]
```

---

### Шаг 6: NIC проверяет целостность

- **CRC** — проверка контрольной суммы
- **FCS** — проверка frame check sequence

Если ошибка → пакет **отбрасывается**.

---

### Шаг 7: RSS вычисляет хэш

NIC извлекает поля из заголовков:
- **IP-адреса** (src, dst)
- **Порты** (src, dst)
- **Протокол** (TCP/UDP)

Вычисляет хэш (Toeplitz) с использованием **RSS-ключа**:
```
hash = toeplitz_hash(src_ip, dst_ip, src_port, dst_port, rss_key)
```

**Пример:** `hash = 0xABCD1234`

---

### Шаг 8: NIC определяет очередь через RETA

```
index = hash % 128 = 0xABCD1234 % 128 = 52
queue_id = RETA[52] = 2
```

**Пакет пойдёт в очередь 2.**

---

### Шаг 9: NIC берёт дескриптор из RX-кольца очереди 2

NIC берет из кольцевой очереди столько дескрпиторов,чтобы вмсестить весь сетевой пакет целиком. `rte_mbuf` указывают на фиксированный и непрерывный кусок памяти(как правило 2 Кбайта - этого хватате для большиснтва обычным пакетов, но `Jambo frames` могут в него не вместиться, поэтому испольузется цепочнка из `rte_bmuf`, которые связывают фреймы одного сетевого пакета в список: `rte_mbuf->next`)

```
RX-кольцо очереди 2:
┌─────────────────────────────────────────┐
│ Дескриптор 0: DD=1 (готов)              │
│ Дескриптор 1: DD=1 (готов)              │
│ Дескриптор 2: DD=0 (свободен) ← head    │
│ Дескриптор 3: DD=0 (свободен)           │
└─────────────────────────────────────────┘
```

NIC берёт **дескриптор 2**.

---

### Шаг 10: NIC копирует пакет через DMA

NIC берёт адрес из дескриптора 2 (`descriptor->rte_mbuf->buf_addr = &data_2`) и **напрямую** (через DMA) копирует туда данные:

```
[Сеть] → [NIC] → DMA → [data_2 в hugepages]
```

**CPU не участвует! Что позваляет его сильно разгрузить**

---

### Шаг 11: NIC заполняет метаданные дескриптора

```
Дескриптор 2:
  buf_addr = &data_2       (не меняется)
  length = 1500            (длина пакета)
  status = DD (Done)       ← пакет готов!
  rss_hash = 0xABCD1234    (если включено)
  vlan = 0                 (если нет VLAN)
```

---

### Шаг 12: NIC сдвигает `head`

```
head = (head + 1) % 512 = 3
```

Теперь `head` указывает на дескриптор 3.

---

### Шаг 13: NIC генерирует прерывание (опционально)

Если накопилось **N пакетов** (порог `write_back`), NIC генерирует **MSI-X прерывание**:

```
[NIC] → MSI-X → [CPU]
```

**В polling-режиме (DPDK)** прерывания **не используются** — приложение само опрашивает очередь.

---

## Приложение забирает пакеты

### Шаг 14: Приложение вызывает `rte_eth_rx_burst()`

```c
struct rte_mbuf *bufs[BURST_SIZE];
uint16_t nb_rx = rte_eth_rx_burst(port_id, 2, bufs, BURST_SIZE);
```

**Что происходит внутри:**

Драйвер смотрит на свой указатель `tail` для очереди 2:

```
RX-кольцо очереди 2:
┌─────────────────────────────────────────┐
│ Дескриптор 0: DD=1 (готов) ← tail       │
│ Дескриптор 1: DD=1 (готов)              │
│ Дескриптор 2: DD=1 (готов)              │
│ Дескриптор 3: DD=0 (свободен) ← head    │
└─────────────────────────────────────────┘
```

---

### Шаг 15: Драйвер «подменяет» буферы

Для **каждого готового дескриптора**:

1. **Берёт `rte_mbuf`, который привязан к дескриптору:**
   ```
   mbuf_A = дескриптор_0.mbuf  (содержит данные пакета)
   ```

2. **Отдаёт `mbuf_A` приложению:**
   ```
   bufs[0] = mbuf_A
   ```

3. **Берёт новый `rte_mbuf` из пула:**
   ```
   mbuf_B = rte_mbuf_raw_alloc(mempool)
   ```

4. **Привязывает `mbuf_B` к дескриптору 0:**
   ```
   дескриптор_0.mbuf = mbuf_B
   дескриптор_0.buf_addr = &mbuf_B.data
   дескриптор_0.DD = 0  (свободен)
   ```

`Получается, что, дескрипторы постоянны, а вот rte_mbuf, к которым они привязаны, нет, они могут меняться`

**Визуально:**
```
ДО:
  Дескриптор 0 → mbuf_A (данные пакета)
  
ПОСЛЕ:
  Дескриптор 0 → mbuf_B (пустой)
  Приложение → mbuf_A (данные пакета)
```

---

### Шаг 16: Драйвер сдвигает `tail`

```
tail = (tail + nb_rx) % 512 = 3
```

---

### Шаг 17: Драйвер обновляет RDT (doorbell)

Драйвер записывает в регистр NIC `RDT` новый `tail`:

```
RDT = 3
```

**Это сообщает NIC:** «Дескрипторы 0, 1, 2 свободны, можешь писать туда новые пакеты».

---

### Шаг 18: Приложение получает массив `rte_mbuf`

```c
for (uint16_t i = 0; i < nb_rx; i++) {
    struct rte_mbuf *pkt = bufs[i];
    // pkt->data → данные пакета
    // pkt->pkt_len → длина
    // pkt->ol_flags → оффлоады
}
```

**Пакеты не копировались!** Приложение получило **указатели** на буферы, которые уже содержат данные.

---


## Возврат буферов

### Шаг 19: Приложение обработало пакет

```c
// Обработка пакета
process_packet(pkt);
```

---

### Шаг 20: Приложение возвращает `rte_mbuf` в пул

```c
rte_pktmbuf_free(pkt);
```

**Что происходит:**

1. **Уменьшается `refcnt`:**
   ```
   mbuf_A.refcnt--
   ```

2. **Если `refcnt == 0`:**
   - `mbuf_A` возвращается в `mempool`
   - Он становится **свободным** для переиспользования

3. **`mempool` теперь содержит `mbuf_A`:**
   ```
   mempool: [mbuf_A (свободен), mbuf_B (занят), ...]
   ```

---

### Шаг 21: Драйвер переиспользует `mbuf_A`

При следующем **пополнении** (в `rte_eth_rx_burst` или фоново):

1. Драйвер берёт `mbuf_A` из `mempool`.
2. Привязывает его к **свободному дескриптору** (например, дескриптор 3):
   ```
   дескриптор_3.mbuf = mbuf_A
   дескриптор_3.buf_addr = &mbuf_A.data
   ```
3. NIC снова может писать в этот буфер.
