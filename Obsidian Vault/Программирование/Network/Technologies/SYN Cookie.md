Связанные темы: [[TCP]]
**SYN cookie** — это техника защиты от **SYN-flood атак** (разновидность DDoS), при которой сервер не хранит состояние полуоткрытых соединений, а кодирует всю нужную информацию в специально сформированный номер последовательности (ISN) .

---

## Как работает SYN cookie

**Обычный TCP handshake (без защиты):**
1. Клиент → SYN → Сервер (сервер создаёт запись в очереди полуоткрытых соединений)
2. Сервер → SYN+ACK → Клиент
3. Клиент → ACK → Сервер (соединение установлено)

**При SYN-flood** атакующий шлёт много SYN-пакетов с поддельными IP, сервер заполняет очередь ожиданием ACK, и легитимные клиенты не могут подключиться .

**Как работают SYN cookies:**

| Шаг | Что происходит |
|-----|----------------|
| 1 | Приходит SYN от клиента. Сервер **не создаёт запись в очереди**  |
| 2 | Сервер вычисляет cookie — хеш от IP/портов клиента и сервера, метки времени и MSS  |
| 3 | Сервер отправляет SYN+ACK, где в качестве ISN (начального номера последовательности) подставляется этот cookie  |
| 4 | Если клиент настоящий, он вернёт ACK с номером cookie+1  |
| 5 | Сервер восстанавливает cookie, проверяет его и при успехе создаёт полноценное соединение  |

## Формула SYN cookie (классическая реализация)

```
Cookie = (t mod 32) << 27 | (mss << 24) | hash(IP_клиента, порт_клиента, IP_сервера, порт_сервера, t)
```

Где:
- **t** — медленно растущая метка времени (обновляется каждые 64 секунды) 
- **mss** — максимальный размер сегмента (кодируется в 3 бита, 8 возможных значений) 
- **hash** — 24-битная криптографическая хеш-функция

## Преимущества и недостатки

### Преимущества
- **Полная безотказность** при атаке — сервер не ведёт учёт полуоткрытых соединений
- **Низкое потребление памяти** — не нужно выделять ресурсы на подозрительные SYN-пакеты 

### Недостатки

| Проблема | Описание |
|----------|----------|
| **Потеря TCP-опций** | В cookie не хватает места для всех опций (window scaling, timestamps, SACK) — производительность соединения может быть ниже  |
| **Нет ретрансляции SYN+ACK** | Если ACK клиента потерян, сервер не может переотправить SYN+ACK — соединение не установится  |
| **Дополнительная нагрузка на CPU** | Хеширование каждого SYN+ACK требует ресурсов процессора  |
| **Уязвимость к ACK-flood** | Атакующий может слать поддельные ACK, заставляя сервер тратить CPU на проверку cookie  |

## Как включить (в Linux)

```bash
# Проверить текущее значение
sysctl net.ipv4.tcp_syncookies

# Включить защиту (рекомендуемое значение — 1)
sudo sysctl -w net.ipv4.tcp_syncookies=1
```

Значения:
- `0` — отключено
- `1` — включается автоматически при обнаружении SYN-flood 
- `2` — включено всегда

По умолчанию в современных дистрибутивах Linux (с Ubuntu 9.04) стоит значение `1` .
