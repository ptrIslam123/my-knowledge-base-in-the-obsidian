**`asyncio`** — это библиотека в Python, которая позволяет писать **конкурентный** (concurrent) код, используя синтаксис `async`/`await`. Её главная задача — эффективно управлять операциями, которые большую часть времени **ждут** (ожидание ответа от базы данных, сетевого запроса, чтения файла с диска).

В отличие от многопоточности, `asyncio` работает в **одном потоке** и использует модель **асинхронного ввода-вывода**. **По сути просто очень хороший слой поверх генераторов Python.**

### Ключевая идея: "Ожидание — не блокировка"

Обычный (синхронный) код работает так:
1. Выполняется строка A.
2. Выполняется строка B (которая, например, ждет ответа от сервера 3 секунды) — **весь ваш код стоит на месте**.
3. Только после этого выполняется строка C.

Асинхронный код с `asyncio` работает иначе:
1. Выполняется `await some_network_request()` — Python запускает операцию и *ставит текущую корутину (coroutine) на паузу*.
2. В это время управление передается обратно в **Event Loop** (цикл событий).
3. Event Loop берет другую готовую к работе корутину (например, обработку другого пользователя) и запускает её.
4. Когда ответ от сети получен, первая корутина «просыпается» и продолжает работу.

### Основные компоненты asyncio

1.  **Event Loop (Цикл событий)** — главный координатор. Он бесконечно работает, хранит очереди готовых и ждущих задач и переключается между ними при каждом `await`.

2.  **Coroutine (Корутина)** — специальная функция, объявленная через `async def`. Она может приостанавливать своё выполнение через `await`.

3.  **Awaitable (Ожидаемый объект)** — то, что можно использовать с `await`: другая корутина, объекты `Task` или `Future`.

## Обзор генераторов

Если вы уже знакомы с генераторами, пропустите эту часть, но если нет, то именно на них построен asyncio, поэтому очень важно понимать, как они работают.

Прежде всего, причина, по которой генераторы существуют, заключается в том, что они позволяют сделать ваш код более эффективным с точки зрения памяти. Представьте, что у вас есть следующий цикл:

```python
for i in range(100_000_000):
	print(i)
```

Если бы `range` был не генератором, а функцией, возвращающей список для последующего его перебора, код, подобный вышеприведенному примеру, был бы очень неэффективным в плане использования памяти, поскольку вы бы создали список из 100 миллионов элементов... Однако, поскольку `range` это генератор, по крайней мере в Python 3+, вы генерируете числа только по мере необходимости, одно за другим, не сохраняя всю последовательность в памяти.

Есть несколько способов создания генераторов, но мы сосредоточимся на функциях генераторов. Эти генераторы определяются как любые другие функции, но используют для возврата данных оператор `yield`. Этот оператор превращает обычную функцию в генератор, которая вместо того, чтобы выполняться сразу, может приостанавливать и возобновлять свое состояние при вызове `next(iterator)`.

Возьмем, к примеру, следующую функцию-генератор:

```python
def generator():   
	yield 'hello'   
	yield 'world'iterator = generator()
```

  
Когда вы вызываете генератор, Python видит ключевое слово `yield` и вместо того, чтобы запустить код внутри функции, как он это обычно делает — возвращает объект генератора. Как только у нас есть объект генератора, мы можем вызвать `next(iterator)` и он запустит код функции до первого/следующего оператора  `yield`:

```python
print(next(iterator))  # Output: helloprint(next(iterator))  # Output: world
```

Если мы попробуем вызвать `next(iterator)` еще раз, генератор вызовет исключение  `StopIteration`, поскольку в функции генератора больше нет операторов yield.

Еще одна интересная функция генераторов Python — это `yield from` — возможность из генератора вызывать подгенератор или итерируемый объект, что позволяет вам создавать цепочку генераторов!

```python
def generator():   
	yield 'hello'
	
def another_generator():   
	yield from generator()
	
iterable = another_generator()
print(next(iterable))  # Output: hello
```

  
Генераторы — это нечто большее, чем я говорю, например, генераторные включения, которые похожи на списочные включения, но создаются с круглыми скобками вместо квадратных, и возможность отправлять данные генераторам с помощью  `iterator.send(value)`. Однако для данной статьи важно помнить о генераторах, что они позволяют запускать и останавливать функцию, сохраняя ее состояние!

## Цикл событий

Цикл событий, который отвечает за запуск и управление всеми текущими задачами, является ядром asyncio и первое, что мы воссоздадим с помощью генераторов. Хотя цикл событий asyncio написан на языке C, его проще всего представить в виде списка, содержащего все текущие задачи. Пока что представьте эти задачи просто как объекты-генераторы. Менеджер цикла событий будет проходить по каждой задаче в списке и использовать функцию  `next(task)` для запуска каждой из них. Затем эта задача будет запущена, и когда она будет выполнять работу, связанную с вводом-выводом, например, спать, она будет использовать ключевое слово  `yield` чтобы приостановить свое выполнение и вернуть управление этому циклу событий, который затем перейдет к следующей задаче в цикле.

Вот пример этого — у нас есть две задачи, обе печатают свой номер и затем приостанавливают свое выполнение. Поскольку менеджер цикла событий — это тот, кто вызывает `next()`, после того как задача приостановлена, он получает управление обратно и затем переходит к выполнению следующей задачи в цикле.

```python
def task1():   
	while True:       
		print('Task 1')       
		yield

def task2():   
	while True:       
		print('Task 2')       
		yield

event_loop = [task1(), task2()]

while True:   
	for task in event_loop:       
		next(task)
```

  
Впоследствии вывод этого кода будет выглядеть следующим образом и будет продолжаться до бесконечности, поскольку обе функции генератора никогда не завершатся из-за циклов `while True`.

```
Task 1
Task 2
Task 1
Task 2
…
```

## Sleep

Если мы возьмем тот же код сверху, мы можем добавить подгенераторы к нашим задачам с помощью `yield from`. Ниже я добавил спящий генератор, который приостановит выполнение задач, пока не истечет указанное время. Это работает, потому что `sleep`будет продолжать выдавать результат, пока не пройдет определенное количество секунд, после чего он выйдет из цикла `while`. 
Поскольку в `sleep` больше нет операторов   `yield`,  возникает исключение `StopIteration`, которое сигнализирует оператору `yield from` в функциях задач о необходимости перейти к следующей строке кода.

```python
import time

def sleep(seconds):   
	start_time = time.time()   
	while time.time() - start_time < seconds:       
		yield 

def task1():   
	while True:       
		print('Task 1')       
		yield from sleep(1)

def task2():   
	while True:       
		print('Task 2')       
		yield from sleep(5)
		
event_loop = [task1(), task2()]

while True:   
	for task in event_loop:       
		next(task)
```

Выход:

```
Task 1
Task 2
Task 1
Task 1
Task 1
Task 1
Task 2
Task 1
…
```

## От yield к await

Теперь мы можем взять приведенный выше код и перейти от использования `yield` к `await` с помощью dunder-метода  `__await__` и ключевого слова `async`. Когда класс имеет метод `__await__`, мы можем использовать ключевое слово  `await` перед экземпляром класса, чтобы вызвать его. В asyncio вы обычно работаете с  объектами `Task` через функцию, например `asyncio.create_task`. Эти  объекты `Task` наследуются от объекта asyncio `Future`, у которого есть метод `__await__` . Мы также можем использовать `await` перед корутиной, которая является объектом, созданным при вызове функции с  ключевым словом `async` перед ней. Корутины похожи на функции-генераторы в том смысле, что выполнение корутины также можно приостанавливать и возобновлять.

Можете думать о  ключевом слове `await` как о простом синониме `yield from` с некоторыми дополнительными правилами проверки. Таким образом, при написании кода `await object` вы в основном говорите либо yield из метода `__await__` в экземпляре класса «object», ИЛИ «object» может быть другой корутиной (вроде подгенератора).

---
### Что происходит в await

```python
await coro()
```

1. Начинается `coro()`
2. Если `coro()` не может продолжить исполнение(встречается `await asyncio.sleep()` или дескриптор/сокет еще не готов), то замораживает текущий контекст и передает управление обратно планировщику корутин.
3. Управление уходит в event loop
4. Event loop передает управление **другой задаче/корутине** из очереди, которая может продолжить выполнение
5. Новая задача/корутина продолжает исполнение с последнего места остановки
6. Через некоторое время управление возвратиться`coro()` с места последней остановки
7. И так пока корутина не закончит полностью свое исполнение.

**Из очереди event loop может взять только задачу (Task), а не просто корутину. Корутина становится задачей только после `create_task` или аналогичных функций. Просто `await coro()` не создает задачу.**

---
### Корутина (coroutine)
```python
async def my_func():      # Это корутина
    await asyncio.sleep(1)
    return "result"
```

### Task (задача)
```python
task = asyncio.create_task(my_func())  # Задача — обертка над корутиной
```
- Задача — это корутина, поставленная в очередь event loop'а
- У задачи есть состояние (выполняется, завершена, отменена)

## ВАЖНЕЙШИЙ МОМЕНТ: ПЕРЕКЛЮЧЕНИЯ И ПОСЛЕДОВАТЕЛЬНОСТЬ

##### Последовательное исполнение

```python
# ПОСЛЕДОВАТЕЛЬНО (но с переключениями)
await coro1()   # [====coro1 с перерывами====]
await coro2()   #                              [====coro2 с перерывами====]
# Другие задачи могут выполняться в перерывах
```

Тут `coro2` не будет никак исполняться, пока не закончится полное исполнение `coro1()`, хоть обе функции являются асинхронными. Дело в кооперативности, пусть `coro2` и является асинхронной функцией, планировщик не может ее исполнить, так как она не находится в очереди задач на исполнение после прерывания текущей исполняющейся корутине.

##### Возможно конкурентное/псевдопараллельное исполнение 

```python
# ПАРАЛЛЕЛЬНО (через create_task)
t1 = create_task(coro1())   # [====coro1 с перерывами====]
t2 = create_task(coro2())   # [====coro2 с перерывами====]
await t1; await t2
# coro1 и coro2 выполняются в одном временном интервале
```

Путь этот код и почти поход с предыдущим кодом, в нем есть существенное отличие. Мы не `await``им напрямую асинхронные функции, а `asyncio.task`. Каждое
`asyncio.create_task(coro())` -  помещает в очередь задач планировщика корутин и возвращает ссылку на задачу. `await` над задачей означает дождаться завершения исполнения задачи. Почему этот вариант является конкурентным/псевдопараллельное исполнением? Дело в том что, обе задачи `t1 & t2` попадут в очередь задач и потому каждый вызов `await` предоставляет возможность этим задачам быть избранными планировщиком на продолжение выполнения, вместо варианта где `coro2` не может быть вообще поставлена на исполнение, пока не закончит полное исполнение `coro1`.

**Псевдопараллельное - в данном случает имеется ввиду что, нет реальной параллельности(несколько физических workers/ядер выполняющих вычисления), есть только конкурентность (переключение между задачами для эмуляции псевдопараллельности).**

### Как asyncio/await выглядит в коде

### 1. Пример

```python
import asyncio
import time

async def fetch_data(delay, name):
    print(f"Начинаю загрузку {name}...")
    await asyncio.sleep(delay)  # Симулируем сетевой запрос
    print(f"Закончил загрузку {name} через {delay} секунд.")
    return f"Данные от {name}"

# Плохой пример (последовательно):
async def bad_example():
    start = time.time()
    result1 = await fetch_data(2, "Сервер A")
    result2 = await fetch_data(1, "Сервер B")
    print(result1, result2)
    print(f"Последовательно заняло: {time.time() - start:.1f} сек")
    # Вывод: ~3 секунды (2 + 1)

# Хороший пример (конкурентно):
async def good_example():
    start = time.time()
    # Создаем задачи, но НЕ ждем их сразу
    task1 = asyncio.create_task(fetch_data(2, "Сервер A"))
    task2 = asyncio.create_task(fetch_data(1, "Сервер B"))

    # Теперь ждем обе сразу
    result1 = await task1
    result2 = await task2
    print(result1, result2)
    print(f"Конкурентно заняло: {time.time() - start:.1f} сек")
    # Вывод: ~2 секунды (максимум из 2 и 1, а не сумма!)

# Запуск
asyncio.run(good_example())
```


### 2. Пример

Чтобы не писать цикл для ожидания каждой задачи, можно использовать встроенную функцию `asyncio.gather()`. На вход она принимает итерабельный объект с задачами, а возвращает `Future` для группы задач. Это существенно упрощает код.

```python
import asyncio
import time


async def sleep():
    await asyncio.sleep(1)


async def sum(name, numbers):
    total = 0
    for number in numbers:
        print(f"Task {name}: Computing {total}+{number}")
        await sleep()
        total += number
    print(f"Task {name}: Sum = {total}")


async def main():
    tasks = [
        asyncio.create_task(sum("A", [1, 2])),
        asyncio.create_task(sum("B", [1, 2, 3])),
    ]
    await asyncio.gather(*tasks)

asyncio.run(main())
```

### Где asyncio неэффективен (и когда НЕ надо его использовать)

`asyncio` дает выигрыш только для **I/O-bound** задач (операции ввода-вывода: сеть, диски, базы данных). Он **бесполезен и даже вреден** для **CPU-bound** задач (сложные вычисления, обработка изображений, шифрование).

Если внутри корутины выполняется `while True: calculate_pi()` — это заблокирует весь Event Loop, и никакие другие корутины не запустятся. Для таких задач нужны отдельные процессы (`concurrent.futures.ProcessPoolExecutor`).
### Что еще важно знать новичку

1.  **`asyncio.run()`** — главная точка входа в асинхронную программу (запускает Event Loop и закрывает его).
2.  **Нельзя смешивать асинхронный и синхронный код** просто так. Вызов `async` функции из обычной вернет корутину, но не выполнит её.
3.  **`asyncio.gather()`** — удобный способ запустить несколько корутин параллельно и дождаться всех.
4.  **`asyncio.create_task()`** — запускает корутину в фоне (как «запоминаем и забудем» но контролируемо).
5.  В Python 3.11+ появились улучшения: `asyncio.TaskGroup` (как `gather`, но удобнее для обработки ошибок) и `asyncio.to_thread()` для безопасного выполнения синхронного I/O кода.
