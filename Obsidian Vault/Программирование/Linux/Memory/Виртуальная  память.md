
### 1. Основная идея
Каждому процессу в Linux ядро предоставляет иллюзию, что он один владеет всей оперативной памятью (обычно 4 ГБ в 32-битных системах или огромным адресным пространством в 64-битных). Это **виртуальное адресное пространство**. Физическая память (RAM) — это общий ресурс, которым управляет ядро, подставляя нужные физические кадры (frames) под виртуальные страницы (pages) процессов.

### 2. Структура виртуального адресного пространства (на примере x86-64)
Пространство делится на две главные части:

*   **Пространство ядра (Kernel space):** Верхняя часть (например, последние 1 ГБ в 32-бит с раскладкой 3:1). Общая для всех процессов, но недоступна для кода пользовательского режима. Здесь живут код ядра, его данные, структуры, отображение физической памяти и т.д.
*   **Пространство пользователя (User space):** Нижняя часть (например, первые 3 ГБ в 32-бит). Уникальна для каждого процесса.

**Типичная layout пользовательского пространства (растущее от низших адресов к высшим):**

1.  **Зарезервировано:** Нижние страницы (например, первые 64 КБ) часто не отображены для отлавливания ошибок разыменования NULL-указателя.
2.  **Текст программы (.text):** Исполняемый код, только для чтения.
3.  **Данные (.data):** Инициализированные статические/глобальные переменные.
4.  **BSS (.bss):** Неинициализированные статические/глобальные переменные (заполнены нулями).
5.  **Куча (Heap):** Динамически выделяемая память (`malloc`, `new`). Растет в сторону высших адресов.
6.  **Библиотеки:** Код и данные разделяемых библиотек (например, `libc.so`), отображаются в процесс.
7.  **Стек (Stack):** Локальные переменные, аргументы функций, адреса возврата. Растет в сторону низших адресов (обычно начинается с высокого адреса).
8.  **Аргументы командной строки и переменные окружения (argv, envp):** Обычно в самом верху пользовательского пространства, чуть ниже стека.

В 64-битных системах пространство огромно (128 ТБ пользовательского пространства в Linux x86-64), поэтому промежутки между регионами очень велики.

### 3. Ключевые структуры данных в ядре

Ядро отслеживает память каждого процесса с помощью:

*   **`struct mm_struct`:** Главная структура, описывающая все виртуальное адресное пространство процесса. У каждого процесса есть своя `mm_struct` (или она разделена, как в потоках).
*   **`struct vm_area_struct` (VMA):** Описывает **непрерывный** регион виртуальной памяти с одинаковыми атрибутами (права доступа, флаги, отображенный файл и т.д.). Например, текстовый сегмент, куча, каждое отображение файла через `mmap` — это отдельные VMA.
    *   Список VMA процесса — это по сути "оглавление" его памяти. Ядро быстро ищет VMA по адресу (через красно-черное дерево).
*   **Таблица страниц (Page Table):** Иерархическая структура (обычно 4-х или 5-уровневая в x86-64), которая напрямую переводит виртуальный адрес в физический (или указывает на его отсутствие). Каждый процесс имеет свою таблицу страниц.

### 4. Механизм преобразования адресов (Translation)

1.  Виртуальный адрес делится на **индексы** для каждого уровня таблицы страниц и **смещение** внутри страницы (обычно страница = 4 КБ).
2.  **CR3** (указатель на таблицу страниц) хранится в регистре процессора и уникален для каждого процесса (меняется при переключении контекста).
3.  Аппаратный модуль **MMU (Memory Management Unit)** в процессоре проходит по уровням таблицы (PML4 → PGD → PUD → PMD → PTE), используя индексы из виртуального адреса.
4.  Последняя запись **PTE (Page Table Entry)** содержит физический адрес кадра страницы (frame), флаги (RW, Present, User/Supervisor, Dirty, Accessed).
5.  Если бит **Present = 0**, возникает **Page Fault** (исключение отсутствия страницы).

### 5. Обработка Page Fault

Ядро ловит это исключение и смотрит, по какому адресу оно произошло:
*   **Некорректный доступ (Segmentation Fault):** Адрес не входит ни в одну VMA или нарушает права доступа (попытка записи в read-only) → процессу посылается SIGSEGV.
*   **Действительный доступ, но страница не загружена:**
    *   **Анонимная страница** (куча, стек): Ядро выделяет свободный физический кадр, заполняет его нулями (для защиты данных), обновляет PTE.
    *   **Файловая страница** (отображение файла, библиотека): Ядро находит нужный блок на диске, читает его в физический кадр, обновляет PTE. Это и есть **demand paging** (подкачка по требованию).
*   **Доступ к странице, вытесненной в swap:** Ядро находит другую страницу в RAM, сбрасывает её на диск в swap-область (если она "грязная"), читает нужную страницу с диска обратно в RAM, обновляет PTE.

### 6. Системные вызовы для управления памятью

*   `brk()` / `sbrk()`: Изменяет границу кучи (используется `malloc` внутри).
*   `mmap()`: Универсальный механизм. Может:
    *   **Анонимно** отобразить новые страницы (используется `malloc` для больших блоков, стеки потоков).
    *   **Отобразить файл** в память (файлы на диске, библиотеки).
    *   Создать отображения для межпроцессного взаимодействия (shared memory).
*   `munmap()`: Удаляет отображение.
*   `mprotect()`: Меняет права доступа к региону (например, сделать страницу только для чтения).

### 7. Иерархия таблиц страниц в x86-64 (4-уровневая)

## Корректное разбиение 48-битного виртуального адреса для 4-уровневой иерархии:

```
Виртуальный адрес (48 значимых бит из 64):
[47:39] - 9 бит - Индекс в PML4 (Уровень 4)
[38:30] - 9 бит - Индекс в PDP  (Уровень 3)
[29:21] - 9 бит - Индекс в PD   (Уровень 2)
[20:12] - 9 бит - Индекс в PT   (Уровень 1)
[11:0]  - 12 бит - Смещение внутри страницы
```


## Почему именно так?

### 1. **Размер страницы = 4КБ = 4096 байт = 2¹² байт**
- Чтобы адресовать любой байт внутри страницы, нужно **12 бит** (от 0 до 4095)
- Эти 12 бит — **последние 12 бит** адреса

### 2. **Оставшиеся 48 - 12 = 36 бит делятся на 4 части по 9 бит**
- Каждая таблица (PML4, PDP, PD, PT) занимает **ровно одну страницу 4КБ**
- На странице 4КБ помещается 4096 байт
- Каждая запись таблицы = **8 байт** (64 бита)
- Количество записей = 4096 / 8 = **512 записей**
- Чтобы проиндексировать 512 записей, нужно log₂(512) = **9 бит**


## Как работает обход таблиц на практике

**Старт:** В регистре CR3 хранится **физический адрес PML4 таблицы**

**Шаг за шагом:**

```
CR3 (физический адрес PML4 в RAM)
     |
     |  + PML4_index × 8 (каждая запись 8 байт)
     v
[ PML4 Table ] ← в физической памяти
     |  Запись #PML4_index (PML4E)
     |  Содержит: Физический адрес PDP таблицы + флаги
     v
[ PDP Table ] ← в физической памяти  
     |  + PDP_index × 8
     v
     Запись #PDP_index (PDPTE)
     |  Содержит: Физический адрес PD таблицы + флаги
     v
[ PD Table ] ← в физической памяти
     |  + PD_index × 8
     v
     Запись #PD_index (PDE)
     |  Содержит: Физический адрес PT таблицы + флаги
     v
[ PT Table ] ← в физической памяти
     |  + PT_index × 8
     v
     Запись #PT_index (PTE)
     |  Содержит: Физический адрес 4КБ кадра + флаги
     v
[ Physical Frame 4KB ] ← реальная страница в RAM
     + Смещение (12 бит)
     v
Искомый физический байт!
```

## Почему именно 4 уровня?

**Математика емкости:**

1. **Один PML4** (512 записей) может адресовать:
   - 512 PDP таблиц ×

2. **Одна PDP** (512 записей) может адресовать:
   - 512 PD таблиц ×

3. **Одна PD** (512 записей) может адресовать:
   - 512 PT таблиц ×

4. **Одна PT** (512 записей) может адресовать:
   - 512 физических страниц по 4КБ

**Итого:** 512 × 512 × 512 × 512 × 4КБ = 512⁴ × 4КБ

512⁴ = 2⁹ × 2⁹ × 2⁹ × 2⁹ = 2³⁶ = 68,719,476,736 страниц

68,719,476,736 × 4КБ = **256 ТБ виртуального адресного пространства**

# Полное руководство по адресации виртуальной памяти в x86-64 (4-уровневая иерархия)

## 1. ФУНДАМЕНТАЛЬНЫЕ КОНЦЕПЦИИ

### 1.1. Виртуальная vs Физическая память
- **Виртуальная память** — иллюзия, что у процесса есть всё адресное пространство
- **Физическая память** — реальные ячейки RAM
- **Преобразование** — аппаратное отображение VA → PA через таблицы страниц

### 1.2. Канонические адреса (обязательное правило)
```
63                48 47                                    0
├──────────────────┼────────────────────────────────────────┤
│   Старшие 16     │          Младшие 48 бит               │
└──────────────────┴────────────────────────────────────────┘
    ДОЛЖНЫ БЫТЬ:         Используются для
    либо все 0          реальной адресации
    либо все 1
```
- **User space**: `0x0000 0000 0000 0000` — `0x0000 7FFF FFFF FFFF` (128 ТБ)
- **Kernel space**: `0xFFFF 8000 0000 0000` — `0xFFFF FFFF FFFF FFFF` (128 ТБ)

## 2. РАЗБИЕНИЕ ВИРТУАЛЬНОГО АДРЕСА (48 бит)

### 2.1. Базовая математика
- **Размер страницы**: 4 КБ = 4096 байт = 2¹² байт
- **Для смещения внутри страницы нужно**: 12 бит
- **Остается на поиск страницы**: 48 - 12 = 36 бит
- **Эти 36 бит делятся на 4 индекса**: 36 ÷ 4 = 9 бит на индекс

### 2.2. Точное разбиение
```
Биты 47-39: PML4 индекс (9 бит)  → 512 возможных значений (0-511)
Биты 38-30: PDP индекс  (9 бит)  → 512 возможных значений (0-511)  
Биты 29-21: PD индекс   (9 бит)  → 512 возможных значений (0-511)
Биты 20-12: PT индекс   (9 бит)  → 512 возможных значений (0-511)
Биты 11-0:  Смещение    (12 бит) → 4096 возможных значений (0-4095)
```

## 3. ИЕРАРХИЯ ТАБЛИЦ СТРАНИЦ (4 УРОВНЯ)

### 3.1. Структура каждого уровня
```
УРОВЕНЬ 4: PML4 (Page Map Level 4) / PGD
├─ Размер: 4 КБ (одна страница)
├─ Записей: 512 (по 8 байт каждая)
├─ Содержимое: PML4E (указывает на PDP таблицу)
└─ Хранится: Физический адрес в регистре CR3

УРОВЕНЬ 3: PDP (Page Directory Pointer) / PUD
├─ Размер: 4 КБ
├─ Записей: 512  
├─ Содержимое: PDPTE (указывает на PD таблицу или 1G страницу)
└─ Флаг PS=1: Превращает в указатель на 1G страницу

УРОВЕНЬ 2: PD (Page Directory) / PMD
├─ Размер: 4 КБ
├─ Записей: 512
├─ Содержимое: PDE (указывает на PT таблицу или 2M страницу)
└─ Флаг PS=1: Превращает в указатель на 2M страницу

УРОВЕНЬ 1: PT (Page Table)
├─ Размер: 4 КБ
├─ Записей: 512
├─ Содержимое: PTE (указывает на физический кадр 4K)
└─ Содержит: Физический адрес + флаги доступа
```

### 3.2. Формат записи таблицы (общий для всех уровней)
```
63        52 51                    12 11    9 8 7 6 5 4 3 2 1 0
├───────────┼───────────────────────┼───────┼─┼─┼─┼─┼─┼─┼─┼─┼─┤
│ Reserved  │   Physical Address    │ Avail │ │ │D│A│ │ │U│R│P│
│   (0)     │     (40 бит)          │ (OS)  │ │ │ │ │ │ │/│/│ │
└───────────┴───────────────────────┴───────┴─┴─┴─┴─┴─┴─┴─┴─┴─┘
                                              │ │ │ │ │ │ │ │ └─ Present (1=в памяти)
                                              │ │ │ │ │ │ │ └─── Read/Write (1=запись)
                                              │ │ │ │ │ │ └───── User/Supervisor (1=user)
                                              │ │ │ │ │ └─────── PWT (стратегия записи)
                                              │ │ │ │ └───────── PCD (кэширование)
                                              │ │ │ └─────────── Accessed (был доступ)
                                              │ │ └───────────── Dirty (была запись)
                                              │ └─────────────── PAT (атрибуты кэша)
                                              └───────────────── PS (только уровни 2-3)
```

## 4. ПОЛНЫЙ ПРОЦЕСС ПРЕОБРАЗОВАНИЯ (PAGE WALK)

### 4.1. Алгоритм преобразования VA → PA
```
ВХОД: Виртуальный адрес VA, Регистр CR3

1. ИЗВЛЕЧЬ ИНДЕКСЫ из VA:
   PML4_idx = (VA >> 39) & 0x1FF
   PDP_idx  = (VA >> 30) & 0x1FF  
   PD_idx   = (VA >> 21) & 0x1FF
   PT_idx   = (VA >> 12) & 0x1FF
   offset   = VA & 0xFFF

2. НАЧАТЬ С CR3 (адрес PML4):
   pml4_entry_addr = CR3 + (PML4_idx × 8)

3. ПРОЧИТАТЬ PML4E:
   pml4e = read_physical(pml4_entry_addr)
   ЕСЛИ pml4e.P == 0 → PAGE FAULT
   pdp_table_addr = pml4e.physical_address

4. ПРОЧИТАТЬ PDPTE:
   pdpte_addr = pdp_table_addr + (PDP_idx × 8)
   pdpte = read_physical(pdpte_addr)
   ЕСЛИ pdpte.P == 0 → PAGE FAULT
   ЕСЛИ pdpte.PS == 1 → КАДР 1G:
        frame_addr = pdpte.physical_address
        PA = frame_addr | (VA & 0x3FFFFFFF) // 30 бит смещения
        КОНЕЦ
   ИНАЧЕ:
        pd_table_addr = pdpte.physical_address

5. ПРОЧИТАТЬ PDE:
   pde_addr = pd_table_addr + (PD_idx × 8)
   pde = read_physical(pde_addr)
   ЕСЛИ pde.P == 0 → PAGE FAULT
   ЕСЛИ pde.PS == 1 → КАДР 2M:
        frame_addr = pde.physical_address  
        PA = frame_addr | (VA & 0x1FFFFF) // 21 бит смещения
        КОНЕЦ
   ИНАЧЕ:
        pt_table_addr = pde.physical_address

6. ПРОЧИТАТЬ PTE:
   pte_addr = pt_table_addr + (PT_idx × 8)
   pte = read_physical(pte_addr)
   ЕСЛИ pte.P == 0 → PAGE FAULT
   frame_addr = pte.physical_address

7. СФОРМИРОВАТЬ PA:
   PA = frame_addr | offset

ВЫХОД: Физический адрес PA
```

### 4.2. Визуальное представление
```
           ВИРТУАЛЬНЫЙ АДРЕС
        [PML4][ PDP][ PD][PT][OFF]
           │     │    │    │    │
    CR3 → PML4   │    │    │    │
           │     │    │    │    │
           ▼     │    │    │    │
         PML4E[PML4] │    │    │    (уровень 4)
           │         │    │    │
           ▼         │    │    │
         PDP Table   │    │    │
           │         │    │    │
           ▼         │    │    │
        PDPTE[PDP]   │    │    │    (уровень 3)
           │         │    │    │
           ▼         │    │    │
         PD Table    │    │    │
           │         │    │    │
           ▼         │    │    │
         PDE[PD]     │    │    │    (уровень 2)
           │         │    │    │
           ▼         │    │    │
         PT Table    │    │    │
           │         │    │    │
           ▼         │    │    │
         PTE[PT]     │    │    │    (уровень 1)
           │         │    │    │
           ▼         │    │    │
        ФИЗИЧЕСКИЙ   │    │    │
          КАДР 4K    │    │    │
           │         │    │    │
           └─────────┴────┴────┘
                     ▼
           ФИЗИЧЕСКИЙ АДРЕС
```

## 5. КЛЮЧЕВЫЕ АППАРАТНЫЕ ОПТИМИЗАЦИИ

### 5.1. TLB (Translation Lookaside Buffer)
- **Назначение**: Кэш результатов трансляции
- **Структура**: Ассоциативная память в процессоре
- **Содержит**: Пары [виртуальная страница → физический кадр]
- **TLB hit**: Мгновенное преобразование (1-3 такта)
- **TLB miss**: Полный page walk (100+ тактов)

### 5.2. Раздельные TLB
- **ITLB**: Для инструкций (кода)
- **DTLB**: Для данных
- **STLB**: Второй уровень (больше, но медленнее)

## 7. РЕАЛИЗАЦИЯ В LINUX ЯДРЕ

### 7.1. Структуры данных
```c
// Четырехуровневая иерархия
typedef struct { unsigned long pgd; } pgd_t;    // PML4
typedef struct { unsigned long pud; } pud_t;    // PDP
typedef struct { unsigned long pmd; } pmd_t;    // PD  
typedef struct { unsigned long pte; } pte_t;    // PT

// Макросы для работы
#define pgd_offset(mm, addr)    // Получить PGD запись
#define pud_offset(pgd, addr)   // Получить PUD запись  
#define pmd_offset(pud, addr)   // Получить PD запись
#define pte_offset_map(pmd, addr) // Получить PTE запись
```

### 7.2. Процесс обработки page fault
1. **Исключение #PF** → ядро получает управление
2. **Анализ адреса** → поиск VMA (vm_area_struct)
3. **Проверка прав** → доступ разрешен?
4. **Выделение кадра** → физической памяти или swap
5. **Построение таблиц** → создание недостающих уровней
6. **Заполнение PTE** → установка физического адреса + флагов
7. **Возврат** → повтор выполнения инструкции

## 8. ПРИМЕР КОНКРЕТНОГО ПРЕОБРАЗОВАНИЯ

### 8.1. Дано:
- Виртуальный адрес: `0x00007FFFFFFFFFF0`
- Размер страницы: 4K
- CR3: `0x1A0000`
