### Формальное описание алгоритма

Алгоритм оперирует двумя параметрами:

1.  **Window Size (w):** Размер окна (временной интервал). Например, 60 секунд.
2.  **Max Requests (n):** Максимальное количество запросов, разрешенное в этом окне.

**Жизненный цикл:**

1.  **Инициализация:** Для каждого пользователя (или ключа API) создается пустой список (лог) временных меток.

2.  **Очистка (перед проверкой):** При поступлении нового запроса система удаляет из лога все временные метки, которые старше, чем `Current Time - Window Size`. Они больше не влияют на лимит.

3.  **Проверка:**
    *   Система смотрит на текущий размер лога (сколько меток осталось после очистки).
    *   **Если** `текущий_размер < Max Requests`:
        *   Запрос разрешается.
        *   Текущая временная метка (`текущее_время`) добавляется в лог.
    *   **Если** `текущий_размер >= Max Requests`:
        *   Запрос отклоняется.
        *   Метка **НЕ** добавляется в лог.

---

Sliding Window Log не разбивает время на фиксированные интервалы. Он смотрит на **реальные последние N секунд** (или любой другой размер окна) относительно момента запроса. Считает количество запросов за эти последние **N** секунд и если > **Max Requests**, то отбрасывает запрос. Если <= **Max Requests**, то принимает этот запрос.

### Где используется Sliding Window Log?

1.  **Высокоточные биллинговые системы:** Если ты платишь за каждый запрос API (например, OpenAI или Google Maps API), они должны считать абсолютно точно, чтобы не обсчитать клиента.
2.  **Строгие юридические или бизнес-лимиты:** Когда нарушение лимита хотя бы на 1 запрос может привести к штрафам или сбоям (например, лимиты на транзакции).
3.  **Сравнительно низконагруженные системы:** Там, где пользователей не миллионы, а тысячи, и можно позволить себе хранить историю.

### Реализация в Redis (классический паттерн)

На практике Sliding Window Log часто реализуют через структуру данных **Sorted Set** в Redis.

Ключ: `rate_limit:{user_id}`
Значение: Временные метки запросов (с одинаковым score и value = timestamp).

```python
# Псевдокод на Python с Redis
import redis
import time

r = redis.Redis()

def allow_request(user_id, limit=5, window_seconds=60):
    key = f"rate_limit:{user_id}"
    now = time.time() * 1000  # миллисекунды
    window_start = now - (window_seconds * 1000)
    
    # 1. Очистка: удаляем все записи старше окна
    r.zremrangebyscore(key, 0, window_start)
    
    # 2. Проверка: считаем сколько осталось
    current_count = r.zcard(key)
    
    if current_count < limit:
        # 3. Добавляем новый запрос
        r.zadd(key, {now: now})
        # 4. Ставим TTL на весь ключ (чтобы Redis сам почистил, если юзер ушел)
        r.expire(key, window_seconds)
        return True
    else:
        return False
```

### Итог

**Sliding Window Log** — это самый точный, но и самый "тяжелый" алгоритм rate limiting. Он гарантирует, что лимит не будет превышен **ни при каких обстоятельствах** в пределах любого скользящего окна времени, но платит за это памятью и вычислительными ресурсами.

Параметры:
- **Window Size:** Размер временного окна (например, 60 секунд, 24 часа).
- **Max Requests:** Максимум запросов за это окно.
