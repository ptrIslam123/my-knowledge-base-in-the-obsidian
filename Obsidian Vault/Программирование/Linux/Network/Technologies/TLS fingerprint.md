## Связанные темы: [[TLS]]

# JA3

**JA3** — это метод создания отпечатка (**fingerprint**) TLS-клиента на основе параметров, которые клиент передаёт в самом начале защищённого соединения — в сообщении **ClientHello** .

Простыми словами: JA3 — это «цифровой отпечаток» приложения или библиотеки, которая устанавливает TLS-соединение.


JA3 был изобретён в **Salesforce в 2017 году** .  
Сегодня проект больше не поддерживается Salesforce, но его создатель **John Althouse** продолжает развивать тему в **FoxIO-LLC** (современные JA4 и JA4+).

### Главная идея

> JA3 позволяет **идентифицировать клиентское приложение** по тому, **как** оно общается, а не по тому, **с кем** и **откуда**.

Даже если вредоносная программа меняет IP-адреса, домены, порты или сертификаты, её **JA3-отпечаток остаётся неизменным** .

JA3 применяется в задачах **информационной безопасности**, **анализа сетевого трафика** и **обнаружения ботов**.

### Основные сценарии

| Сценарий | Описание |
|:---|:---|
| **Обнаружение вредоносного ПО** | Многие семейства малвари используют одинаковые или схожие TLS-стеки, что даёт постоянный JA3-отпечаток . |
| **Блокировка ботов** | Антибот-системы (Cloudflare, DataDome) вычисляют JA3 и блокируют небраузерные клиенты (Python requests, curl) . |
| **Threat Hunting** | Аналитик ищет редкие или подозрительные JA3 в логах и получает отправную точку для расследования . |
| **White-листы** | В закрытых средах можно разрешить только известные JA3 (например, корпоративный браузер) . |

### Важное замечание

JA3 не следует воспринимать как классический IOC (Indicators of Compromise) — это **поведенческий индикатор уровня «инструмент» (Pyramid of Pain)**. Сам по себе он мало что даёт без контекста (SNI, JA3S, URI, поведение сессии) .

## 3. Как работает JA3 (технически)

Перед установкой TLS-соединения клиент отправляет серверу сообщение **ClientHello**. Оно передаётся **в открытом виде** (даже в HTTPS) и содержит технические параметры клиента .

JA3 анализирует **5 конкретных полей** этого сообщения .

| № | Поле | Что означает | Откуда берётся |
|:---|:---|:---|:---|
| 1 | **SSL/TLS Version** | Версия протокола | Первые 2 байта ClientHello |
| 2 | **Cipher Suites** | Список поддерживаемых алгоритмов шифрования | Список 2-байтовых идентификаторов |
| 3 | **Extensions** | Список TLS-расширений | Список 2-байтовых ID расширений |
| 4 | **Elliptic Curves** | Поддерживаемые эллиптические кривые (из расширения Supported Groups) | 2-байтовые ID кривых |
| 5 | **EC Point Format** | Форматы точек эллиптических кривых | 1-байтовые значения |

### 3.3. Формирование строки JA3

Все значения собираются в одну строку в строгом порядке :

```
SSLVersion,CipherSuites,Extensions,EllipticCurves,ECPointFormat
```

**Правила**:
- значения внутри одного поля разделяются знаком `-`
- поля разделяются запятой `,`
- если поле отсутствует, оно остаётся пустым

#### Пример (реальный) 

Исходные параметры:
```
Version:     769 (TLS 1.2)
Ciphers:     47,53,5,10,49161,49162,49171,49172,50,56,19,4
Extensions:  0,10,11
Curves:      23,24,25
Format:      0
```

Собранная строка:
```
769,47-53-5-10-49161-49162-49171-49172-50-56-19-4,0-10-11,23-24-25,0
```

### 3.4. Финальный хеш (MD5)

Полученная строка хешируется алгоритмом **MD5** .

Пример для строки выше:
```
ada70206e40642a3e4461f35503241d5
```

## JA3S

Существует также **JA3S** — отпечаток **сервера** (ServerHello). Он использует поля: `Version, Cipher, Extension`.  
Комбинация **JA3 + JA3S** позволяет идентифицировать **всю криптографическую сессию** целиком .

## 4. Примеры JA3-отпечатков (известные)

| Приложение / Вредонос | JA3-хеш |
|:---|:---|
| Tor Browser (стандартный) | `e7d705a3286e19ea42f587b344ee6865`  |
| Trickbot (банковский троян) | `6734f37431670b3ab4292b8f60f29984`  |
| Emotet | `4d7a28d6f2263ed61de88ca66eb011e3`  |
| Remcos RAT | `a85be79f7b569f1df5e6087b69deb493`  |
| WannaCry | `e7d705a3286e19ea42f587b344ee6865` (совпадает со старым Tor)  |

> **Важно:** JA3 не уникален на 100% — разные приложения могут давать **одинаковый** хеш, если используют одинаковый TLS-стек. Поэтому нужен контекст .

---

## 5. Плюсы JA3

| Плюс | Описание |
|:---|:---|
| **Не зависит от IP/домена** | Отпечаток остаётся неизменным при смене C2-инфраструктуры . |
| **Пассивный метод** | Не требует внедрения в клиентское приложение, работает на уровне сети . |
| **Платформонезависимость** | Работает независимо от ОС и языка разработки . |
| **Эффективен против DGA-малвари** | Даже если домены генерируются динамически, JA3 клиента остаётся тем же . |
| **Удобен для white-листов** | В контролируемых средах можно разрешить только ожидаемые JA3 . |

---

## 6. Минусы и ограничения JA3

| Минус | Пояснение |
|:---|:---|
| **Чувствительность к порядку** | Если перемешать cipher suites или расширения — хеш изменится, хотя клиент тот же . |
| **Уязвимость к GREASE** | Браузеры добавляют случайные «мусорные» значения (GREASE), которые меняют JA3 . |
| **Подделываемость (spoofing)** | Злоумышленник может скопировать JA3 легитимного браузера . |
| **Коллизии** | Разные клиенты могут давать одинаковый JA3 (например, используют одну библиотеку) . |
| **Не учитывает эволюцию TLS** | Новые расширения TLS 1.3 могут не покрываться алгоритмом . |
| **Требует контекста** | Сам по себе JA3 не говорит «хороший/плохой» — нужен SNI, JA3S, URI, поведение . |
| **Проект не развивается** | Оригинальный JA3 больше не поддерживается Salesforce . |

# JA4

**JA4** — это метод создания отпечатка (**fingerprint**) клиента на основе параметров, которые клиент передаёт в самом начале защищённого соединения — в сообщении **ClientHello** для TLS , так же как и JA3.

Простыми словами: JA4 — это «цифровой отпечаток» приложения или библиотеки, которая устанавливает TLS-соединение, но в отличие от JA3, JA4 **структурирован, стабилен и устойчив к обходным техникам**.

JA4 был разработан компанией **FoxIO, LLC в 2023 году** как прямая замена устаревшему JA3. 

### Главная идея

> JA3 оказался неэффективен против современных браузеров, которые намеренно меняют порядок расширений и добавляют случайные значения (GREASE). JA4 решает эти проблемы, вводя **сортировку** и **структурированный формат** отпечатка.

JA4 применяется в задачах **информационной безопасности**, **антибот-защиты** и **анализа сетевого трафика**.

| Сценарий | Описание |
|:---|:---|
| **Обнаружение вредоносного ПО** | JA4 позволяет идентифицировать TLS-стек малвари, даже если она меняет IP/домены . |
| **Блокировка ботов** | Cloudflare, AWS WAF, DataDome используют JA4 для фильтрации автоматических запросов . |
| **Идентификация мобильных приложений** | JA4 одного мобильного приложения одинаков на всех устройствах — можно создать правило разрешения . |
| **Threat Hunting** | Поиск редких или подозрительных JA4 в логах . |
| **White-листы** | В закрытых средах можно разрешить только известные JA4 (например, корпоративный браузер) . |

---

## Как работает JA4 (технически)

JA4 анализирует и кодирует **7 характеристик** TLS-сообщения ClientHello:

| Поле | Что означает | Формат в JA4 |
|:---|:---|:---|
| **Протокол** | TCP или QUIC | `t` или `q` |
| **TLS версия** | 1.2, 1.3 и т.д. | `12`, `13` |
| **Тип SNI** | Доменное имя или IP-адрес | `d` (domain) или `i` (IP) |
| **Количество Cipher Suites** | Сколько шифров предложил клиент (без учёта GREASE) | число (например, `15`) |
| **Количество Extensions** | Сколько расширений предложил клиент (без учёта GREASE) | число (например, `17`) |
| **ALPN** | Протокол прикладного уровня (h2, http/1.1) | `h2`, `h1` и т.д. |
| **Хеш Cipher Suites** | Truncated SHA256 от **отсортированного** списка шифров | 12 hex-символов |
| **Хеш Extensions** | Truncated SHA256 от **отсортированного** списка расширений | 12 hex-символов |

JA4 имеет **структурированный, человеко-читаемый формат** :

```
[Protocol][Version][SNI_Type][Cipher_Count][Extension_Count][ALPN]_[Cipher_Hash]_[Extension_Hash]
```

### Реальный пример

```
t13d1517h2_8daaf6152771_02713d6af862
```

Расшифровка:

| Символ         | Значение                                                      |
| :------------- | :------------------------------------------------------------ |
| `t`            | Протокол TCP (а не QUIC)                                      |
| `13`           | TLS версия 1.3                                                |
| `d`            | SNI является доменным именем                                  |
| `15`           | Клиент предложил 15 Cipher Suites (после фильтрации GREASE)   |
| `17`           | Клиент предложил 17 Extensions (после фильтрации GREASE)      |
| `h2`           | ALPN = HTTP/2                                                 |
| `8daaf6152771` | Truncated SHA256 от **отсортированного** списка Cipher Suites |
| `02713d6af862` | Truncated SHA256 от **отсортированного** списка Extensions    |

## Ключевое отличие от JA3: сортировка

**Проблема JA3**: если один и тот же клиент пришлёт cipher suites в порядке `A,B,C` → один хеш, а в порядке `C,B,A` → другой хеш. Браузеры намеренно меняют порядок, чтобы сломать JA3 .

**Решение JA4**: перед вычислением хеша JA4 **сортирует cipher suites и extensions в числовом порядке**. Это делает отпечаток стабильным независимо от порядка, в котором браузер отправил параметры.

### Фильтрация GREASE

Современные браузеры (Chrome, Firefox) добавляют в TLS-рукопожатие специальные «мусорные» значения (GREASE, RFC 8701) для проверки устойчивости промежуточного ПО .

JA4 **фильтрует эти значения** перед подсчётом количества и вычислением хеша. Поэтому:
- `Cipher_Count` = количество **реальных** шифров (без GREASE)
- `Extension_Count` = количество **реальных** расширений (без GREASE)
- Хеши считаются только от реальных значений

# JA4_raw

Помимо стандартного JA4 (хешированного), существует **JA4_raw** — полная версия, которая содержит сами списки значений, а не только их хеши .

Пример JA4_raw:
```
t13d1517h2_002f,0035,009c,009d,1301,1302,1303,c013,c014,c02b,c02c,c02f,c030,cca8,cca9_0005,000a,000b,000d,0012,0017,001b,0023,0029,002b,002d,0033,4469,fe0d,ff01_0403,0804,0401,0503,0805,0501,0806,0601
```

Где:
- после первого подчёркивания — отсортированный список Cipher Suites
- после второго подчёркивания — отсортированный список Extensions
- после третьего подчёркивания — отсортированный список Elliptic Curves и Signature Algorithms

**JA4_raw** полезен для глубокого анализа, но для идентификации обычно достаточно хешированной версии JA4 .

## Семейство JA4: JA4, JA4S, JA4H, JA4L, JA4X

JA4 — это не один метод, а **целое семейство** отпечатков для разных протоколов и сценариев :

| Название | Расшифровка | Что анализирует | Применение |
|:---|:---|:---|:---|
| **JA4** | JA4 TLS Client | ClientHello (клиент) | Идентификация TLS-клиентов |
| **JA4S** | JA4 TLS Server | ServerHello (сервер) | Идентификация TLS-серверов |
| **JA4H** | JA4 HTTP | HTTP-заголовки запроса | Детектирование HTTP-клиентов |
| **JA4L** | JA4 Lighter | Только первые 12 байт TLS ClientHello | Лёгкий парсинг |
| **JA4X** | JA4 X.509 | Сертификат | Идентификация по сертификату |
| **JA4SSH** | JA4 SSH | SSH-рукопожатие | Идентификация SSH-клиентов |
| **JA4QUIC** | JA4 QUIC | QUIC Initial Packet | Идентификация QUIC-клиентов |

## JA3 vs JA4: таблица сравнения

| Характеристика | JA3 | JA4 |
|:---|:---|:---|
| **Год создания** | 2017 | 2023  |
| **Формат** | MD5 хеш (32 hex) | Структурированная строка + хеши (36 символов)  |
| **Чувствительность к порядку** | **Высокая** — порядок влияет на хеш | **Низкая** — сортировка перед хешированием  |
| **GREASE** | Не фильтруется (меняет отпечаток) | Фильтруется по RFC 8701  |
| **SNI / ALPN** | Не учитываются | Учитываются в структуре отпечатка  |
| **Протоколы** | Только TLS | TLS, QUIC, HTTP, SSH  |
| **Человеко-читаемость** | Нет (только хеш) | Да — можно понять параметры по строке  |
| **Актуальность** | Устаревает, но используется | Современный стандарт |
| **Проект** | Не поддерживается (Salesforce) | Активно развивается (FoxIO)  |
| **Поддержка WAF** | Cloudflare, AWS (базовая) | Cloudflare, AWS WAF, nDPI, Akamai  |

## Плюсы JA4

| Плюс | Описание |
|:---|:---|
| **Стабильность** | Сортировка и фильтрация GREASE делают отпечаток неизменным для одного клиента |
| **Устойчивость к обходу** | Злоумышленнику сложнее подделать JA4, чем JA3 |
| **Человеко-читаемость** | По строке `t13d1517h2` видно, что за клиент  |
| **Мультипротокольность** | Поддержка TCP, QUIC, HTTP, SSH  |
| **Активная поддержка** | Интегрирован в Cloudflare, AWS, nDPI, Wireshark  |
| **Меньше коллизий** | Сортировка уменьшает вероятность разных клиентов с одним отпечатком |

---

## Минусы и ограничения JA4

| Минус | Пояснение |
|:---|:---|
| **Не абсолютная уникальность** | Разные приложения могут иметь одинаковый JA4 (например, одинаковый TLS-стек)  |
| **Подделываемость (spoofing)** | Злоумышленник может подделать JA4 (например, с помощью `uTLS` или `curl-impersonate`)  |
| **Требует контекста** | Сам по себе JA4 не говорит «хороший/плохой» — нужны другие сигналы (User-Agent, IP, поведение)  |
| **Не все расширения покрыты** | JA4 не учитывает некоторые специфические параметры TLS |
| **Проблема Safari (эфемерные расширения)** | У Safari JA4 может меняться из-за расширений PSK/Session Ticket (решается патчем «игнорирование эфемерных расширений») |

## JA4 в антибот-системах (Cloudflare, AWS WAF, nDPI)

Cloudflare, AWS WAF и nDPI активно используют JA4 для фильтрации трафика .

### Как это работает на практике

1. Вы отправляете HTTPS-запрос (например, через `curl` или `requests`).
2. Сервер на уровне балансировщика/WAF анализирует ClientHello.
3. Вычисляется JA4.
4. Если JA4 не совпадает с ожидаемым для браузера — запрос блокируется или отправляется на дополнительную проверку (JavaScript-челлендж, CAPTCHA).
