**Связанные темы:** [[Docker]]

**LXC (Linux Containers)** — это технология контейнеризации на уровне операционной системы, которая позволяет запускать несколько изолированных Linux-систем на одном хосте, используя ядро хоста .

LXC существует с 2008 года и является проверенным низкоуровневым решением для запуска Linux-контейнеров . Это **не виртуализация** в классическом понимании (без гипервизора и эмуляции железа), а использование встроенных механизмов ядра Linux для изоляции процессов .

### Ключевая особенность

LXC создает **системные контейнеры** — окружения, максимально приближенные к полноценным виртуальным машинам, но без накладных расходов на запуск отдельного ядра и эмуляцию аппаратного обеспечения . Внутри такого контейнера работает полноценная ОС со своими процессами, файловой системой, сетевыми интерфейсами и пользователями .

---
## Архитектура и механизмы работы

LXC использует **те же механизмы**, что и [[Docker]] (namespaces + cgroups). Разница — в **философии**: LXC создает полноценную ОС внутри контейнера, Docker — изолированное окружение для одного приложения .

| Механизм | Назначение |
|----------|------------|
| **Namespaces** (пространства имен) | Изоляция процессов, сетей, PID, файловых систем, IPC и пользователей  |
| **Cgroups** (контрольные группы) | Ограничение ресурсов: CPU, память, диск I/O, количество процессов  |
| **AppArmor / SELinux** | Мандатное управление доступом для дополнительной безопасности |
| **Seccomp** | Фильтрация системных вызовов  |
| **Chroot (pivot_root)** | Изоляция корневой файловой системы |

## LXC vs Docker: сравнительная таблица

| Характеристика | LXC | Docker |
|----------------|-----|--------|
| **Уровень** | Операционная система | Приложение  |
| **Что внутри** | Полноценная Linux-ОС с systemd, SSH, несколькими сервисами | Одно приложение / микросервис  |
| **Изоляция** | Процессы, файловые системы, сеть (полноценная ОС) | Процессный уровень, строгий sandbox  |
| **Цель** | Эмуляция VM без накладных расходов  | Упаковка и оркестрация приложений (CI/CD)  |
| **Управление образами** | Нет центрального репозитория | Docker Hub, развитая система образов  |
| **Оркестрация** | Базовые скрипты, нет встроенных средств | Kubernetes, Docker Swarm, Compose  |
| **Сложность настройки** | Выше — ручная настройка сети, безопасности, хранилища  | Ниже — простой CLI, готовые образы |
| **Безопасность по умолчанию** | Требуется донастройка  | Более строгие настройки "из коробки"  |

## Преимущества и ограничения LXC

### Преимущества
- **Почти нативная производительность** — нет оверхэда гипервизора 
- **Экономия ресурсов** — контейнеры легче ВМ 
- **Быстрый старт** — запуск за секунды 
- **Гибкость** — внутри полноценная ОС с любыми сервисами 
- **Поддержка непривилегированных контейнеров** — повышенная безопасность 

### Ограничения
- **Только Linux** — нельзя запустить Windows или другую ОС 
- **Общее ядро с хостом** — риск: уязвимость в ядре может затронуть все контейнеры 
- **Более сложная настройка** по сравнению с Docker 
- **Нет встроенной оркестрации** и центрального репозитория образов 

---

## Когда выбирать LXC?

- **Системная контейнеризация** — нужно окружение, максимально похожее на отдельный сервер 
- **Несколько сервисов внутри одного контейнера** (веб-сервер + БД + кеш) 
- **Инфраструктурные сервисы** в гомелабе/датацентре (Proxmox) 
- **Легкий хост для Docker** — LXC как базовый слой для запуска Docker-контейнеров

## Сравнение с Docker
### 1. Техническая основа (Одинаковая)
В LXC используются те же самые механизмы, что и в [[Docker]]:
- **Пространства имен (Linux Namespaces):** Изолируют процессы, сеть, PID-ы, пользователей и файловые системы.
- **Контрольные группы (cgroups):** Ограничивают ресурсы (CPU, память, дисковый ввод-вывод).

То есть технически LXC и Docker — это **братья по ядру Linux**. Они не эмулируют железо (как QEMU/KVM), не используют гипервизор — значит, это **не виртуализация** в классическом понимании (аппаратной).

---

### 2. Почему же LXC называют «легкой виртуалкой» (Разница в подходах)
Слово «контейнер» (container) описывает механизм изоляции, но не описывает то, **ЧТО** мы кладем внутрь этого контейнера. Вот здесь и кроется главное отличие:

- **Docker (Контейнер приложений):** Внутрь кладется **только одно приложение** и его библиотеки. Там нет системы инициализации (systemd), нет SSH-сервера, нет cron. Если приложение упадет — контейнер остановится. Это "микроконтейнер" для одной задачи.

- **LXC (Системный контейнер):** Внутрь кладется **целая операционная система**. Внутри LXC запускается собственный процесс `init` (или systemd), у него есть свои демоны, свои логи, свой SSH. По поведению и по ощущениям от администрирования **он ведет себя как отдельный сервер (VM)**. 

Именно за это сходство в поведении (можно зайти по SSH, перезагрузить ОС внутри, настроить сеть как на физическом сервере) LXC в обиходе и называют «легкой виртуалкой». Это **маркетингово-поведенческое** сравнение, а не техническое описание механизма работы.

## Безопасность: привилегированные и непривилегированные контейнеры

LXC был **первым** рантаймом, реализовавшим поддержку непривилегированных контейнеров после появления user namespaces в ядре Linux .

### Привилегированные контейнеры
- Запускаются от root на хосте
- Менее безопасны — при компрометации возможен выход на хост

### Непривилегированные контейнеры (рекомендованы)
- Запускаются от обычного (не-root) пользователя 
- Используют **user namespaces** для маппинга UID/GID: UID 0 (root) внутри контейнера отображается на непривилегированный UID на хосте (например, 1000000) 
- Это самый безопасный режим работы
