Собрал для тебя полную инструкцию, чтобы ты мог к ней возвращаться. Она состоит из двух частей: **пополнение OpenRouter** и **настройка VPN для Linux** (чтобы OpenCode мог работать без ошибок).

### Часть 1: Пополнение баланса OpenRouter через Plati.Market

Этот способ позволяет оплатить доллары на OpenRouter рублями с карты МИР или через СБП, не передавая никому свой пароль или API-ключ.

**Шаг 1. Выбери и оплати товар на Plati.Market**
Найди лот с названием вроде «**OpenRouter | Пополнение Баланса | Без Входа**». Выбери нужную сумму в долларах (например, $10) и оплати заказ удобным тебе рублёвым способом.

**Шаг 2. Создай платёжную ссылку в своём аккаунте OpenRouter**
Сразу после оплаты на Plati перейди в свой аккаунт OpenRouter по адресу `openrouter.ai/settings/credits`.
1.  Включи тумблер **«Use crypto»**.
2.  В поле `Amount` введи **ровно ту сумму**, которую ты купил на Plati (целое число, например, `10`). Важно: не нужно добавлять комиссию 5% — продавец берёт её на себя.
3.  Нажми **«Purchase»**.
4.  Откроется страница оплаты (Coinbase). **Не плати там!** Просто **скопируй ссылку** из адресной строки браузера. Она начинается с `payments.coinbase.com/...`.

**Шаг 3. Передай ссылку продавцу**
Вернись на страницу заказа на Plati.Market и вставь скопированную ссылку в специальное поле (или отправь в «Переписку с продавцом»). После этого система автоматически оплатит счёт, и кредиты зачислятся на твой баланс OpenRouter в течение 1–3 минут.

> **Важно:** После зачисления кредитов возврат средств невозможен. Если что-то пошло не так, пиши продавцу в раздел «Переписка с продавцом».

### 🔒 Часть 2: Настройка VPN на Linux (для работы OpenCode)

Чтобы OpenCode мог использовать OpenRouter без ошибок «Forbidden», тебе нужен VPN с современным протоколом. Я рекомендую **ART VPN**, так как он принимает карты РФ и использует **VLESS Reality** — протокол, который российские провайдеры пока не блокируют.

Поскольку отдельного приложения для Linux у ART VPN нет, тебе нужно настроить его через сторонний клиент.

**Шаг 1. Получи ссылку для подключения**
Напиши в поддержку ART VPN и попроси **ссылку для подключения** (`vless://...`) или **конфигурационный файл** для ручного импорта.

**Шаг 2. Установи клиент на Linux**
Самый простой вариант — **Hiddify**. Он поддерживает VLESS Reality и работает как AppImage (не требует сложной установки).
1.  Скачай файл `HiddifyNext-*.AppImage` с официального сайта.
2.  Открой терминал в папке с файлом и дай ему права на выполнение:
    ```bash
    chmod +x HiddifyNext-*.AppImage
    ```
3.  Запусти его:
    ```bash
    ./HiddifyNext-*.AppImage
    ```

**Шаг 3. Импортируй конфиг и подключись**
1.  В Hiddify нажми **«+»** или **«Add Config»** и выбери **«Import from Clipboard»**, если ты скопировал ссылку `vless://`, или импортируй файл вручную.
2.  Выбери добавленный сервер и нажми кнопку подключения.
3.  **Включи режим TUN** (туннелирование всего системного трафика). Для этого приложению потребуются права root — введи пароль `sudo`.

**Шаг 4. Проверь работу**
Открой терминал и проверь, что трафик идёт через VPN:
```bash
curl -I https://www.google.com
```
Если команда вернёт ответ (например, `HTTP/2 200`), значит VPN работает.

> **Совет:** Если Hiddify не запустится, проверь наличие библиотеки FUSE: `sudo apt install libfuse2`.

### 🔌 Часть 3: Подключение OpenCode к OpenRouter

Когда баланс пополнен и VPN включён, останется только «скормить» ключ OpenCode.
1.  Запусти OpenCode в папке с проектом: `opencode`
2.  Выполни команду `/connect` и выбери **OpenRouter** из списка.
3.  Вставь свой API-ключ (тот, что начинается с `sk-or-v1-...`).
4.  Выполни `/models` и выбери модель (например, DeepSeek или Qwen).

Эта инструкция должна помочь тебе пройти весь путь от оплаты до работающего агента. Если на каком-то из шагов что-то пойдёт не так, возвращайся к этому плану.

# 📘 Полный гайд: весь трафик Linux через прокси телефона

## 🎯 Сценарий

- **Ноутбук** с Kali Linux
- **Телефон** раздаёт Wi-Fi, на нём запущено приложение `VPN Hotspot & Proxy`
- Приложение поднимает на телефоне **SOCKS5** и **HTTP** прокси
- Цель: весь трафик ноутбука идёт через прокси телефона (то есть через VPN на телефоне)

**Почему именно `tun2proxy`:**  
Он единственный из рассмотренных инструментов умеет:
- передавать **домены** в SOCKS5 (аналог `socks5h` — обязательно для этого приложения),
- заворачивать **DNS** (UDP) в TCP, потому что SOCKS5 не умеет UDP,
- работать без ручных правил `iptables`.

`redsocks` в этой связке **не работает** — проверено: HTTP-прокси отвечает `502` на HTTP/1.0-запросы redsocks, а SOCKS5 работает только с передачей домена, чего redsocks не умеет.

---

## 📋 Часть 1. Подготовка (один раз)

### 1.1. Установить Rust и Cargo

В Kali:

```bash
sudo apt update
sudo apt install rustc cargo -y
```

Проверить:
```bash
cargo --version
rustc --version
```

### 1.2. Установить `tun2proxy` через cargo

```bash
cargo install tun2proxy
```

Это скачает и соберёт бинарник. Займёт пару минут.

После установки бинарник будет здесь:
```
~/.cargo/bin/tun2proxy-bin
```

⚠️ **Важно:** именно `tun2proxy-bin`, а не `tun2proxy`. Так называется файл в пакете `tun2proxy 0.8.4`.

### 1.3. Добавить `~/.cargo/bin` в PATH

Для **zsh** (Kali по умолчанию использует zsh):
```bash
echo 'export PATH="$HOME/.cargo/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

Для **bash**:
```bash
echo 'export PATH="$HOME/.cargo/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

Проверить:
```bash
tun2proxy-bin --version
```
Ожидаемый вывод: `tun2proxy 0.8.4 ...`

### 1.4. Создать алиас для быстрого запуска

Для zsh:
```bash
cat >> ~/.zshrc << 'EOF'

# VPN через телефон (tun2proxy + SOCKS5)
alias vpnphone='sudo $HOME/.cargo/bin/tun2proxy-bin --setup --bypass 10.145.36.152 --dns over-tcp --proxy "socks5://10.145.36.152:10810"'
EOF
source ~/.zshrc
```

⚠️ **Проверь IP-адрес телефона** — он может измениться при следующем подключении. См. раздел 2.1.

---

## 📱 Часть 2. Как узнать параметры прокси

### 2.1. Узнать IP телефона (шлюз) и IP прокси

**На телефоне:**
1. Открой `VPN Hotspot & Proxy`
2. Запусти VPN и прокси
3. Запиши:
   - **IP прокси** (например, `10.145.36.152`)
   - **Порт SOCKS5** (например, `10810`)
   - **Порт HTTP** (например, `8080`)

**На ноутбуке** (в том же Wi-Fi):
```bash
ip route | grep default
```
Пример вывода:
```
default via 10.145.36.152 dev wlan0 proto dhcp src 10.145.36.216 metric 600
```
- `10.145.36.152` — это шлюз (он же обычно IP прокси)
- `wlan0` — твой Wi-Fi интерфейс

Если IP прокси из приложения отличается от шлюза — используй **IP из приложения**, а шлюз оставь для `--bypass`.

### 2.2. Проверить, что прокси доступен и работает

**Проверка порта:**
```bash
nc -zv 10.145.36.152 10810
```
Должно быть `open` / `succeeded`.

**Проверка SOCKS5 через `socks5h` (обязательно `h`!):**
```bash
curl -s -x socks5h://10.145.36.152:10810 https://ifconfig.me; echo
```
Должен вернуть IP твоего VPN (например, `31.77.107.84`).

⚠️ Если используешь `socks5://` **без** `h` — получишь ошибку `cannot complete SOCKS5 connection`. Это потому что приложение требует передачи домена, а не IP.

**Проверка HTTP (альтернативный вариант):**
```bash
curl -s -x http://10.145.36.152:8080 https://ifconfig.me; echo
```

**Сравнить с реальным IP:**
```bash
echo "Реальный:"; curl -s https://ifconfig.me; echo
echo "Через прокси:"; curl -s -x socks5h://10.145.36.152:10810 https://ifconfig.me; echo
```

---

## 🚀 Часть 3. Запуск (каждый раз)

### 3.1. Включить Wi-Fi и раздачу с телефона

1. На телефоне включи Wi-Fi раздачу
2. Запусти VPN
3. Запусти прокси в `VPN Hotspot & Proxy`
4. Убедись, что ноутбук подключён к раздаче

### 3.2. Проверить IP прокси (не изменился ли)

```bash
ip route | grep default
```

Если IP изменился — обнови алиас (см. раздел 5.1).

### 3.3. Запустить tun2proxy

**Вариант А — через алиас:**
```bash
vpnphone
```

**Вариант Б — полной командой:**
```bash
sudo ~/.cargo/bin/tun2proxy-bin --setup \
  --bypass 10.145.36.152 \
  --dns over-tcp \
  --proxy "socks5://10.145.36.152:10810"
```

Что означают флаги:
- `--setup` — автоматически настроить маршруты и DNS
- `--bypass 10.145.36.152` — трафик к прокси идёт напрямую (не через туннель), иначе петля
- `--dns over-tcp` — DNS-запросы заворачиваются в TCP и идут через SOCKS5 (SOCKS5 не умеет UDP)
- `--proxy socks5://...` — адрес прокси

**Терминал не закрывать** — tun2proxy работает в переднем плане.

### 3.4. Проверить, что всё работает

**Во втором терминале:**

```bash
# IP через прокси
curl -s https://ifconfig.me; echo
# Должен вернуть IP твоего VPN (например, 31.77.107.84)

# Обычные сайты
curl -sI https://google.com | head -1
curl -sI https://github.com | head -1

# DNS
dig +short google.com
```

Открой браузер и проверь любой сайт.

### 3.5. Выключить

Вернись в терминал с `tun2proxy` и нажми `Ctrl+C`.

Проверь, что интернет вернулся:
```bash
curl -s https://ifconfig.me; echo
```
Должен вернуть твой **реальный IP** (не VPN).

---

## 🛠 Часть 4. Если что-то пошло не так

### 4.1. DNS не работает (сайты не открываются)

Используй `--dns over-tcp` (уже включён в алиас). Если всё равно не работает, попробуй:

```bash
sudo ~/.cargo/bin/tun2proxy-bin --setup \
  --bypass 10.145.36.152 \
  --dns virtual \
  --proxy "socks5://10.145.36.152:10810"
```

### 4.2. Приватный прокси — ошибка «routing loop»

Добавь `--bypass` не только для IP прокси, но и для всей приватной подсети:
```bash
--bypass 10.0.0.0/8
```

### 4.3. После `Ctrl+C` пропал интернет

Маршруты не восстановились. Лечится так:

```bash
sudo systemctl restart NetworkManager
```

Или вручную:
```bash
ip route
# Найди строку "default via <шлюз> dev <интерфейс>"
# Если её нет — добавь:
sudo ip route add default via 10.145.36.152 dev wlan0
# Замени на свои значения
```

В крайнем случае — перезагрузка.

### 4.4. Порт SOCKS5 не отвечает

```bash
nc -zv 10.145.36.152 10810
```
Если `refused` / `timed out`:
- приложение на телефоне не запущено,
- порт изменился (проверь в приложении),
- ноутбук не в той же сети,
- фаервол на телефоне блокирует.

### 4.5. `tun2proxy-bin: command not found`

Полный путь: `~/.cargo/bin/tun2proxy-bin`. Если команда не найдена — либо PATH не обновлён (`source ~/.zshrc`), либо cargo установил бинарник в другое место. Проверь:
```bash
ls ~/.cargo/bin/ | grep tun2proxy
```

### 4.6. SOCKS5 отвечает «cannot complete SOCKS5 connection»

Ты используешь `socks5://` вместо `socks5h://`. Для `tun2proxy` это неважно — он всегда передаёт домен. Но при проверке через `curl` — используй именно `socks5h://`.

## 🔄 Часть 5. Обслуживание

### 5.1. Обновить IP прокси в алиасе

Если IP телефона изменился (например, другая сеть), открой `~/.zshrc`:
```bash
nano ~/.zshrc
```
Найди строку с `alias vpnphone=...` и замени `10.145.36.152` на новый IP. Затем:
```bash
source ~/.zshrc
```

### 5.2. Обновить `tun2proxy`

```bash
cargo install tun2proxy --force
```

### 5.3. Удалить `tun2proxy` полностью

```bash
cargo uninstall tun2proxy
# удалить алиас из ~/.zshrc вручную
```

## 📌 Часть 6. Как это работает (для понимания)

```
┌─────────────┐          ┌──────────────────┐          ┌──────────────┐
│ Приложение  │──TCP/UDP─▶│   tun2proxy      │──SOCKS5─▶│   Телефон    │
│ на ноутбуке │          │  (TUN-интерфейс) │          │  (прокси +   │
└─────────────┘          └──────────────────┘          │   VPN)       │
                                                        └──────┬───────┘
                                                               │
                                                               ▼
                                                        ┌──────────────┐
                                                        │   Интернет   │
                                                        │ (через VPN)  │
                                                        └──────────────┘
```

1. `tun2proxy` создаёт виртуальный сетевой интерфейс (TUN).
2. Весь трафик системы заворачивается в этот интерфейс.
3. `tun2proxy` читает пакеты и отправляет их в SOCKS5-прокси на телефоне.
4. Домены передаются **как есть** (не резолвятся локально) — важно для приложения.
5. DNS-запросы (UDP) упаковываются в TCP — потому что SOCKS5 не умеет UDP.
6. Трафик **к самому прокси** (`--bypass`) идёт напрямую, минуя туннель — иначе петля.

## ⚠️ Известные ограничения

1. **UDP, кроме DNS** — не идёт через SOCKS5. Значит, игры, торренты, WebRTC-звонки в браузере могут не работать. Веб, SSH, apt, curl — работают.
2. **ICMP (ping)** — не работает через туннель. Это нормально.
3. **IPv6** — по умолчанию выключен. Если нужен, добавь `--ipv6-enabled`, но не факт, что прокси его поддержит.
4. **Если телефон отключится** — интернет на ноутбуке пропадёт, пока tun2proxy не остановишь (`Ctrl+C`).
5. **При смене Wi-Fi сети** — IP телефона изменится, надо обновить `--bypass` и `--proxy` в алиасе.
